# 指定主管代辦操作說明

日期：2026-10-06；適用版本：v1.21.2。

v1.21.2 補充：主管指定及代辦表單使用可用全寬。員工名單可拖曳右下角或操作「名單高度」滑桿增減高度；調整高度不改勾選、申請內容或授權，也不觸發未儲存提醒。高度只在本次頁面開啟期間保留，重新載入恢復預設。

v1.21.1 補充：指定代辦主管、主管代辦的員工選取與網頁打卡權限，統一採用紙本補登的搜尋、部門篩選、員工卡片與選取計數。主管代辦請假／加班選日期後直接顯示表單，不需另外按「代申請」。單選查看與多選送件仍分開；篩選不清除已選名單。

v1.21.0 補充：主管代辦表單可多選員工批量請假／加班／午餐代登，日曆上方員工只決定查看紀錄的對象；勾選名單才決定本次代辦對象。共用部門審核路徑也移到「主管指定」，與代辦授權分區且權限分開。詳細操作與整批失敗處理參照 `docs/工作台批量代辦與打卡權限說明.md`。

## 第一次設定

1. 系統管理者登入獨立工作台，在「指定代辦主管」選員工。或由完整管理者／人事管理者進入管理者工作台「主管指定」；自訂管理者需有 `admin.supervisors.manage` 權限。
2. 勾選該員工的一位或多位主管，填設定原因後確認儲存。可跨部門，不會按部門自動授權，也不能指定員工本人。全部取消勾選代表撤銷該員工的所有代辦主管。
3. 為主管開通個人網頁密碼。主管以自己的工號與個人網頁密碼登入，選「員工工作台」→「主管代辦」。只有被指定的主管才會出現入口；卡號登入會提示改用本人個人網頁密碼。
4. 主管從「查看紀錄員工」單選被授權的員工，再選請假、加班或午餐團膳，使用月份及日期格操作。下方表單的「代辦員工」才決定單人或多人送件。不需要讓不熟悉系統的員工全部重設密碼；其原卡號自行登入與打卡方式保留。

主管代辦身分不等於管理者角色，不自動獲得全體人事資料、密碼查詢、授權設定、團膳設定或結單權限。身份模擬不能操作代辦或主管授權。

## 請假

- 選日期後表單直接顯示，勾選代辦員工並填假別、開始／結束時間、每人整筆時數、申請事由及代辦原因，勾選本人核准確認後送出。
- 代申請同時記錄主管核准，狀態為「管理部複核中」，仍需管理部終審；不直接成為已核准請假。
- 待主管或待管理部的請假可「代撤回」，在頁面填原因並勾選確認後送出。撤回直接更新原 ID，不新增取消副本；已核准請假不能由此撤回，請聯絡管理部。
- 日期明細顯示原申請狀態、實際申請人與代辦原因，每頁 50 筆。跨日／跨月仍是原紀錄，不拆分或重算整筆時數。
- 員工原自行申請、部門主管審核及管理部終審仍保留。新的代辦指定不取代既有部門審核路徑。

## 加班

- 員工自行提出加班的功能保留，仍依原主管審核規則辦理。
- 指定主管在代辦頁選日期、填內容及代辦原因，勾選核准確認後「代申請並核准」。只限明確授權的員工，不以部門推定權限。
- 新代辦不改寫已有加班。已核准加班不能在此任意修改；原紙本補登的修正／作廢仍由有權限的管理者處理。
- 原加班申請頁按既有部門路徑提供的直屬員工代申請功能保留；若要跨部門或多位主管代辦，使用新的「主管代辦」。

## 午餐團膳

- 員工是否參加團膳、供餐日期及截止時間仍由團膳管理者設定。主管不能替員工加入／退出或更改制度。
- 選日期後，填「用餐／不用餐」及必填代辦原因，按「儲存午餐代登」。直接更新同一員工同一日的原登記。
- 指定主管與員工同樣受每日截止及結單限制，截止後需聯絡團膳管理者，不會因為是主管就繞過截止。
- 全日請假仍預訂時有提醒及「確認取消餐點」，帶入不用餐及原因後仍需確認儲存；不自動取消。
- 只提供被授權員工的午餐狀態及其已交單用餐狀態，不提供全公司餐數、供應商名單、交單歷史或其他員工的資料。

## 授權與稽核

- 每次讀取與送出都重新檢查目前授權，撤銷後舊登入 Token 也不能繼續代辦。多人同時修改主管設定、請假撤回或午餐登記時，舊畫面會被拒絕，請重新整理。
- 授權、代申請、代撤回與午餐異動記錄實際操作者、時間、原因及前後內容；稽核寫入失敗則整筆異動回滾。
- 刪除員工時清除其作為主管或被代辦者的授權。未來重用同一工號不會自動恢復舊授權；歷史請假／加班仍保留原操作者資訊。
- 切換日期／員工／月份時會確認未儲存內容；切換帳號及登出清除授權資料，舊非同步回應不能覆蓋新帳號畫面。

## 備份與部署

- 新表 `supervisor_assignments` 與申請人／原因欄位以新增方式建立，初始授權為空。舊資料 ID、狀態、時數與審核紀錄保留；舊資料沒有申請人欄位時按既有申請人規則顯示，不偽造歷史代辦資訊。
- 完整 SQLite 備份包含主管指定。舊備份還原後建立空授權表，不按部門自動填入。仍須保留個人網頁密碼的金鑰備份。
- 核心資產備份包含後端模組、瀏覽器 JS／CSS、測試與本文件。依 `docs/更新紀錄.md`、`docs/快速部署還原說明.md` 與完整使用手冊執行發版流程。
- GitHub push 不代表打卡鐘主機已升級。更新打卡鐘電腦的程式／安裝檔並重新啟動後，先核對 `/api/browser/health` 的 `data.appVersion`，再設定主管名單。
