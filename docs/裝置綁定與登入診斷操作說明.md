# 裝置綁定與登入診斷操作說明

適用版本：v1.32.0 起。

## 每人最多四台的暫行政策

管理者工作台 → 安全設定 → 遠端打卡規則，保留「啟用裝置綁定」，將「每人裝置上限」設為 4 並儲存。可選 1～4 台；需要安全設定管理權限才能變更，僅有查看權限者可以查看。

- 舊設定尚未保存台數上限時，新版採 4 台；裝置綁定啟停與 GPS 要求沿用既有設定。
- 帳號驗證成功後，第 1～4 個新的裝置 ID 可建立綁定；達上限後，第 5 個新 ID 會被拒絕。
- 已綁定裝置仍須提供正確憑證。同一 ID 缺少或帶錯憑證，不會因尚有名額而直接放行。
- 調低上限不刪除現有裝置，原本持有有效憑證的裝置仍可登入；新 ID 在既有台數降至上限以下前不能加入。
- 停用裝置綁定會略過檢查，且不新增綁定裝置，不適合用來觀察是否累積至 3～4 台。

這裡的「裝置」是瀏覽器保存的識別資料，不是硬體序號。同一電腦使用不同瀏覽器、設定檔、網站來源，可能有不同 ID；無痕模式或清除網站資料後也可能重建 ID。不要只憑名稱相同就認定是同一實體電腦。

## 查看三台以上的員工

安全設定 → 裝置綁定清單，在綁定狀態選「3 台以上待查看」，再以工號、姓名或部門縮小範圍。

1. 開啟該員工「檢視裝置」，比較裝置 ID、平台、綁定時間、最近登入與 IP。
2. 到「裝置登入診斷」搜尋同一工號；切換至全部或成功紀錄，對照不同 ID 的來源網址與瀏覽器。
3. 向員工確認是否切換網址、瀏覽器、設定檔或清除網站資料。來源網址、IP 與 User-Agent 是當次請求的線索，不是實體裝置的可信證明。
4. 確認不再使用的綁定後，再依既有解除流程處理。解除單台只影響該台；解除此人全部裝置僅影響指定工號，畫面會列出影響範圍。

三台以上標記是管理者查看時的提示，不會自行解除裝置或自動認定異常。此版本沒有背景通知或自動處置排程。

## 裝置登入診斷

安全設定 → 裝置登入診斷，預設查看失敗，可切換全部／成功／失敗並搜尋人員或裝置。

- 顯示台北時間今天及前 13 日、最新最多 200 筆診斷；篩選是在這批資料中進行，不代表所有歷史紀錄。
- 可核對時間、登入／切換工作台／打卡階段、結果、錯誤代碼、原因、裝置 ID、平台與瀏覽器、來源網址、IP、憑證有無、當時綁定台數與上限，並展開 User-Agent 等細節。
- 未完成帳號驗證的嘗試不當作已確認員工；輸入帳號只是查詢線索。不可據此認定某位員工本人曾操作。
- 不記錄密碼、卡號、裝置憑證原文或憑證雜湊；一般員工不能取得其他人的診斷，管理者依安全設定查看權限存取。
- 新版開始執行後才有新診斷，不能補回升級前未保存的登入失敗。沒有紀錄也不能證明沒有發生問題。

## 常見代碼與處理

| 代碼／現象 | 意義與處理 |
| --- | --- |
| P211 | 缺少裝置 ID。確認瀏覽器允許網站儲存資料，再重新登入。 |
| P212 | 相同 ID 的綁定憑證缺少或不符。先核對原瀏覽器與網站入口；由管理者確認後解除該筆綁定再登入，不應直接略過驗證。 |
| P213 | 新 ID 遇到每人台數上限。核對既有台數與來源，確認不用的裝置後解除，或在政策允許範圍調整上限。 |
| P214 | 登入工作階段缺少裝置資訊，重新登入。 |
| P215 | 工作階段使用的綁定已解除，重新登入並依目前政策重新綁定。 |
| 一般帳密／頻率／權限錯誤 | 依診斷原因處理，放寬台數不會修正密碼錯誤、登入頻率限制或工作台權限不足。 |
| 隔天需要重新登入 | 登入工作階段有效期為 12 小時；裝置綁定本身沒有每日到期。持原 ID 與有效憑證可以再次登入。 |

公司主機名稱與 IP 網址屬不同網站來源，瀏覽器不共用該網站的裝置資料。統一日常使用的入口，避免兩個網址交替使用。IP 位址改變或瀏覽器版本更新本身不是裝置拒絕條件；需看裝置 ID 與憑證狀態。

## 更新與驗收

先備份真正主機的 SQLite 與 WebCredentials，再於真正主機安裝並重新啟動 v1.32.0，核對健康檢查版號與前台上限。只在開發電腦更新檔案、建置安裝檔或推送 GitHub，都不會改變正式服務。

隔離測試需涵蓋第 1～4 台允許、第 5 台拒絕、原裝置再登入、缺少／錯誤憑證、調低上限不撤銷原綁定、查看／修改權限與診斷資料不外洩。正式驗收以實際受影響員工再登入的結果為準，避免拿營運員工建立測試裝置。
