# 裝置綁定與登入診斷操作說明

適用 v1.40.0。保留每人最多四台、既有權限與操作紀錄；新增管理者確認恢復原裝置及完整條件查詢。更新程式不會自動合併或解除正式綁定。

## 每人最多四台

管理者工作台 → 安全設定 → 遠端打卡規則，保留「啟用裝置綁定」及既有四台上限。上限可選 1～4 台，只有安全設定管理權限可修改；未設定上限時採 4 台。

- 帳號驗證成功後，第 1～4 個新的裝置 ID 可建立綁定；額滿後新 ID 被拒絕。
- 已綁定 ID 仍需有效裝置憑證；缺少或錯誤憑證不因尚有名額而放行。
- 調低上限不刪除既有綁定；原裝置仍須提供有效憑證，新裝置等名額足夠才能加入。
- 停用綁定不新增裝置，既有資料保留；重新啟用後依憑證與上限驗證。

「裝置」是瀏覽器、設定檔及網站來源保存的身分，不是硬體序號。同一電腦的 Edge、Chrome、不同設定檔或網址可能各有 ID；無痕視窗、清除網站資料也可能產生新 ID。名稱、IP 及瀏覽器資訊只供比對，不會用相同 IP 自動合併或放行。

## 憑證備援如何運作

使用固定公司入口、一般瀏覽器視窗及固定設定檔，允許網站儲存與 Cookie。登入資料包括各員工的綁定憑證；不同員工及網站來源分開保存。

1. 前台讀取網站儲存、Cookie 及舊版憑證時，保留不同的候選值，不會先用舊網站儲存值覆蓋 Cookie。
2. 後端只在該員工的綁定中驗證最多三份候選憑證。找到唯一有效綁定後，才確認原裝置 ID，讓前台同步已驗證結果至可用儲存位置。
3. 有效憑證可找回原 ID，不占新名額；候選憑證若同時對應不同綁定，會拒絕自動選擇，請管理者核對。
4. 新登入先檢查儲存是否可寫入並讀回。兩種位置都不能保存且沒有可沿用憑證時，前台阻擋送件，避免反覆新增；已保存且仍可讀回的原憑證可沿用。登入後另回報憑證保存結果供診斷。
5. 登出只結束工作階段，不清除綁定。IP 改變或瀏覽器版本更新本身不會建立新綁定。

「儲存可用」只代表當下可存取，不保證關閉瀏覽器後保留。全部網站資料都遺失時，網頁不能自行證明是同一台實體電腦；須使用下列人工確認流程。恢復後仍應核對無痕模式、關閉瀏覽器時清理資料及公司還原／清理設定。

## 員工申請恢復原裝置

此流程用於原裝置憑證遺失、識別額滿或憑證對應不明而被拒絕登入。有效帳號驗證及管理者核准都是必要條件，不需要重設個人網頁密碼。

1. 在原本電腦、固定入口及一般瀏覽器視窗嘗試登入。遇到適用的綁定錯誤後，按「申請恢復原裝置」。
2. 填員工編號、可用的卡號或個人網頁密碼，以及恢復原因。系統重新驗證帳號；帳密錯誤不能建立申請，申請本身不給予員工工作台或管理權限。
3. 送出後通知管理者，保留同一分頁。申請自送出起有效 **15 分鐘**；按「查看核准結果」取得進度。
4. 管理者核准後，按「完成恢復」。只有這一步成功，才替換管理者選定的一筆舊綁定、使其舊憑證失效並保存新憑證；總筆數不增加，其他綁定不變。
5. 依畫面提示重新登入。完成後正常登出、關閉重開瀏覽器及隔日再次驗證原 ID 沿用、筆數不增加。

超過 15 分鐘、服務重新啟動、帳號驗證資料變更，或選定的原綁定被修改時，須重新申請及核准。重新啟動會使未完成的恢復授權過期，不會撤銷先前已完成的綁定替換。關閉分頁可能遺失申請端的恢復憑證；請勿把申請憑證交給其他人或貼入操作原因。

## 管理者確認恢復

管理者工作台 → 安全設定 → **原裝置恢復申請**。

1. 具「安全設定檢視」權限可查看申請；具「安全設定管理」權限才可核准或拒絕。不能從 IP 相同直接判定可恢復。
2. 先與本人確認實際電腦、日常入口、瀏覽器及問題時間，再對照「裝置綁定清單」和「裝置登入診斷」。
3. 選擇要恢復的**單一原綁定**，核對工號、舊 ID、新瀏覽器 ID、時間與來源，填寫確認原因後核准；無法確認時填原因拒絕。
4. 核准只授權申請端完成，不會立即刪除或替換原裝置。員工完成恢復前，舊綁定仍保留。管理者核准及本人完成分別留痕。
5. 若原綁定在核准前後變更，系統拒絕覆蓋舊快照，請重新查核並提出申請。恢復、狀態與稽核在同一交易中保存，失敗不留下部分替換。

此功能不會自動清理歷次重複綁定。既有「解除此裝置」及「解除此人全部裝置」功能仍存在，但本次更新及人工恢復不會代替管理者執行它們。正式綁定維持原樣，待明確確認後才逐筆處理。

## 裝置綁定清單

安全設定 → 裝置綁定清單，可選「3 台以上待查看」，再依工號、姓名或部門縮小範圍。「檢視裝置」列出 ID、平台、建立時間、最近登入及 IP。三台以上只是人工查核提示，沒有背景自動合併、解除或處置排程。

## 每位員工的登入診斷

安全設定 → **裝置登入診斷**。進入自動查詢台北時間最近 14 日的失敗紀錄。

- 「診斷員工」可選全部或單一工號；設定開始日期、結束日期及全部／成功／失敗，再按「查詢診斷」。每次可查最多 366 天。
- 伺服器先按員工、日期與結果篩選，再以每頁 25 筆顯示，使用上一頁／下一頁查看。**不再只在全公司最新 200 筆裡篩選某位員工。**
- 下方收合的「工作台載入時摘要」仍只含當時最近 14 日最新 200 筆，不套用上方條件，也不代表完整結果；查核以上方伺服器查詢為準。
- 可比對時間、登入／切換工作台／打卡／恢復／保存階段、結果、錯誤代碼、原因、瀏覽器、平台、網址、IP、User-Agent、送出時 ID 與確認後 ID。
- 新欄位顯示新增／沿用／恢復／拒絕、處理前後綁定數、候選憑證數與驗證結果、網站儲存及 Cookie 可用性，以及已保存／部分保存／保存失敗。原憑證仍可讀回但無法重新寫入時另標示「沿用既存憑證」，不誤判為已遺失。舊紀錄沒有的欄位明確標示未記錄，不能推定舊時狀態。
- 工號查詢也能找到輸入該工號但帳密未通過的事件；畫面標明「未確認帳號」，不可認定為本人操作。來源資訊是線索，不能單獨作為實體電腦或違規證據。
- 僅具安全設定檢視權限可讀；不顯示密碼、卡號、裝置憑證、恢復憑證或雜湊。登出、換角色或帳號後清空前次查詢，舊請求回應不會覆蓋新工作階段。

新版只補齊之後發生的診斷，不能補記之前未留下的失敗。伺服器沒收到的連線問題可能沒有紀錄；稽核保存／歸檔政策也影響可查範圍。

## 常見代碼與處理

| 代碼／現象 | 意義與處理 |
| --- | --- |
| P211 | 缺少裝置 ID，確認允許網站儲存後重新登入。 |
| P212 | 相同 ID 沒有有效綁定憑證；先檢查入口與瀏覽器，仍遺失時申請恢復原裝置。 |
| P213 | 新 ID 已達每人上限；由管理者查核並確認是否恢復指定舊綁定，不自動增加台數。 |
| P214 | 登入工作階段缺少裝置資訊，重新登入。 |
| P215 | 工作階段使用的綁定已解除，重新登入並依目前政策驗證。 |
| P216 | 網站儲存與 Cookie 都無法保存；先允許保存。若登入已驗證但保存失敗，保留畫面聯絡管理者，避免反覆新增。 |
| P217 | 候選憑證對應多筆綁定，不能自動選擇；請管理者核對後恢復指定原裝置。 |
| 一般帳密／頻率／權限錯誤 | 依原因處理，放寬台數或恢復綁定不能繞過帳號與角色授權。 |
| 隔天需要重新登入 | 工作階段有效期為 12 小時；綁定本身沒有每日到期，原 ID 與有效憑證仍能再次登入。 |

先備份真正主機的完整 SQLite 與 WebCredentials，再安裝並重新啟動；核對 `/api/browser/health` 的 `data.appVersion` 為 `1.40.0`，重新載入網頁。完整備份包含 `device_recovery_requests`、`employee_devices` 與稽核。核心原始碼備份新增 `device-proof.js`、`device-recovery-store.js`、`device-recovery.js`。

隔離假資料驗收包含四台允許／第五台拒絕、保留備援中的有效候選、多份有效候選拒絕、不同員工憑證拒絕、儲存失敗、管理者權限、未核准／過期／服務重啟、單筆原子替換且總數不變、原綁定版本衝突、稽核失敗回滾、重試不重複替換、伺服器篩選與分頁，以及桌面／手機完整流程。

本機測試、安裝檔產出或 GitHub 推送不代表正式主機已部署。本次不操作正式綁定；日後現場修復仍須由受影響員工確認關閉重開及隔日登入，不能以開發測試取代。
