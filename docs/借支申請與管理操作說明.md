# 借支申請操作說明

更新日期：2026-10-24。適用版本：v1.38.0；基本借支申請自 v1.34.0 提供。正式使用前須確認安裝版本及管理部活動設定。

## 這個功能處理什麼

員工登記想預支的薪資金額，由管理部核准或退回。管理者可整理 Excel 總表，ERP 可讀取申請修訂資料。

核准不表示已發放款項，也不表示薪資已扣回。本功能不辦理付款、還款或直接修改 ERP 薪資。實際發放及扣回依公司的管理作業辦理。

## 首次活動設定

具「借支活動設定」權限的管理者，在「借支申請管理 → 活動設定」填寫：

- 每月開始日、截止日：初始為每月 15 日至 20 日，截止日包含當日，採臺北時間。日期可調整；月份沒有指定日期時使用該月最後一天。
- 單筆金額上限：已確認預計為新臺幣 15,000 元（1.5 萬元），由管理者自行在正式活動設定填寫或調整；實際生效值以儲存結果為準，不能留空後啟用。
- 每月有效筆數上限：計入同月「待審」及「已核准」申請；已退回、撤回及取消不計。
- 預計扣回月份：可選申請當月、之後月份或「尚待確認」。不確定時留待確認，不能以此欄位代表款項已發放。
- 設定原因：留下設定或變更依據。

新功能初始停用，金額與筆數上限須由管理部確認並設定後才可啟用。活動設定適用之後送出的申請；既有申請保留送件時的設定快照。

## 員工操作

1. 以本人帳號登入並開啟「我的借支」。
2. 核對本月開放期間、金額與筆數上限。
3. 填入整數新臺幣金額，可加申請備註。
4. 按「送交管理部審核」。申請直接進入管理部待審清單，不需要主管審核。
5. 從「查看登記月份」選月份，查看本人紀錄、複核結果及說明。管理部紙本補登及後續更正也會顯示在這裡，綠色「補登記」代表紙本已核准，並不代表款項已發放。

待審申請可按「撤回」並填原因。已核准的申請須聯絡管理部處理；員工不能自行改成未核准或直接刪除。需要改金額時，可在仍開放登記且符合筆數上限的情況下，撤回待審申請再送一筆。

此功能只供本人操作，指定代辦主管不能代填或查看其他員工的借支；身份模擬也不能操作。卡號登入與已設定個人網頁密碼登入均依本人的有效登入與裝置綁定驗證。

## 管理者四個子頁

借支管理採與請假、加班相同的頁面架構：標題與操作說明在工作台總覽指標下方、左側導覽列旁的內容區，不放在指標卡上方。左側依權限提供以下四頁：

| 子頁 | 用途 |
| --- | --- |
| 查看登記月份 | 唯讀查詢。先選月份，再以人員、部門及狀態等條件縮小清單；初始列出全部人員，沒有申請的人也保留在名冊。 |
| 管理部待複核 | 保留月份明細與總額的工作頁，提供有權限人員審核、退回及取消。 |
| 紙本核准補登 | 全體人員的逐列填寫表；為不熟悉系統的員工登記已核准紙本，亦可修改原補登紀錄。 |
| 活動設定 | 管理日期、金額、筆數、預計扣回月份及啟用狀態。 |

查詢清單以膠囊呈現狀態：無申請為灰色；待複核及金額為黃色；已取消、已退回及金額為紅色；已複核、補登記及金額為綠色。員工撤回也歸入「已取消」，原始撤回原因仍保留。同人同月有多筆紀錄時逐筆保留，不以單一狀態掩蓋歷史。

## 管理部複核及總表

在「管理部待複核」選月份，核對員工、申請金額與備註後按「審核」，在當前畫面的彈窗確認核准或退回。核准金額不可高於申請額；核准及退回的「審核說明」均為選填。未填說明仍記錄操作者、時間及結果。

待複核或已複核申請可由具審核權限的人員按「取消」，於彈窗填寫必填的取消原因再確認。取消會保留原核准額與完整狀態歷史，並從目前有效核准總額排除；如果 ERP 已入帳，仍須另外在 ERP 核對更正，不會自動沖回款項。

「下載 Excel 總表及明細」會提供兩張工作表：

- 借支申請明細：單號、月份、工號、姓名、部門、狀態、申請與核准金額、時間、審核／取消說明、修訂版本及登記來源；紙本核准列標示「補登記」。
- 總表：筆數、有效申請額、目前核准額及各狀態數量。有效申請額只計待審與核准；核准額只計目前仍核准者。

工號以文字匯出，前導零不省略。總表是申請核對資料，不能直接當作已發放清冊或薪資扣款憑證。

## 紙本核准補登與更正

1. 具「紙本借支補登與修正」權限者進入「紙本核准補登」，選登記月份，在對應員工列輸入金額；備註選填。
2. 核對工號、月份及金額，確認儲存。紙本已經核准，因此直接成為綠色「補登記」，不再送主管或管理部第二次審核。
3. 儲存後可再改同筆金額或備註並確認儲存。系統保留原單號，增加修訂版本，記錄實際操作者、時間及前後內容；員工自己的「查看登記月份」會看見最新內容。
4. 若別人已更新同筆資料，舊畫面會拒絕覆蓋；先重新整理核對。送出時網路中斷先用原畫面重試，避免另建新筆。

紙本可補登過去月份，無須等員工每月開放日期或啟用自行登記；但金額與每月有效筆數上限須先設定完成。新增補登與員工申請共用同月有效筆數，避免重複登記。已離職人員只可補登離職當月或之前。

更正只開放仍有效的紙本核准紀錄；不藉此改寫員工自行送出的申請或已取消紀錄。更正金額仍依該筆初次補登時的上限，原規則快照及預計扣回月份保留；更正既有單不新增每月有效筆數。已取消紙本須核對後另建新筆，取消仍由具審核權限者處理。每次更正都產生 ERP 可讀的修訂事件，已發放或已扣薪資料仍須到 ERP 核對。

## 權限分開管理

管理部的查看、審核、紙本核准補登、活動設定、Excel 匯出各自有權限。紙本權限為 `admin.salary_advances.paper`，只授予紙本新增及更正，不同時授予員工申請的複核或取消。查詢只回傳名冊所需的工號、姓名、部門與離職日期，不附卡號或銀行資料。

新版「完整管理者」模板包含這些管理權限；舊模板「一般管理者（既有模板）」保留原範圍。升級不自動增加既有帳號的借支紙本權限，請由帳號權限管理明確選取新版模板或以自訂權限授權並儲存。擁有其他考勤管理或主管代辦權限，不等於可以讀取借支財務資料。

外部 ERP 使用獨立 `salary_advances` 讀取權限；原有 API Key 不自動取得此權限。啟用串接前應由開發者檢查金鑰範圍。

真正開發者原有的全域稽核紀錄、資料庫備份與維運權限仍可能接觸借支資料。這是高階維運權限的既有範圍，不表示開發者自動取得借支業務審核權；公司仍須限制哪些人可持有此高階權限。

## 常見狀況

| 畫面或訊息 | 處理方式 |
| --- | --- |
| 活動尚未啟用 | 管理部先完成金額及筆數設定，再確認啟用。 |
| 不在登記期間 | 核對臺北時間及當月設定；不接受偽造月份補送。 |
| 有效筆數已達上限 | 先查看待審／核准申請；不要重複送件。 |
| 申請已被更新 | 可能已由他人審核，重新整理後再核對；系統不覆蓋舊版本。 |
| 送出時網路中斷 | 保留原輸入再試；相同送件識別碼不會重複建單。重新載入後應先查看紀錄。 |
| 核准但沒有領到款項 | 核准是申請結果，請聯絡管理部確認實際發放作業。 |
| ERP 金額與申請不同 | 核對來源單號及修訂；已發放／已扣薪與申請金額屬不同階段，不應直接覆寫。 |

ERP 開發交接、讀取契約及測試清單請參閱 [ERP借支串接交接說明](ERP借支串接交接說明.md)。
