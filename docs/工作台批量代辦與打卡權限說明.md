# 工作台批量代辦與網頁打卡權限

日期：2026-10-07；適用版本：v1.24.0。

## 員工名單寬度與高度

- 「設定主管的員工」、下方「指定的代辦主管」及共用審核路徑表單，使用工作台可用全寬，不再限制 850px，與網頁打卡權限區右側齊平。
- 三個名單高度可分別調整：電腦拖曳名單右下角；電腦、手機或鍵盤也可操作下方「名單高度」滑桿。預設 186px，可在 100 至 1200px 間調整；超過可見範圍的員工仍可在名單內捲動。
- 高度只影響顯示，不改勾選、搜尋條件、授權或送出內容，也不觸發未儲存提醒。本次頁面開啟期間依選取器用途記住高度，切換設定員工或重繪保留；重新載入頁面恢復預設，不寫入營運資料庫。共用此選取器的主管代辦及紙本補登也提供相同高度控制。

## 員工申請表

- 請假申請、加班申請：電腦版第一列為開始日期／開始時間／結束日期／結束時間；第二列為假別或加班員工／每人時數／原因。較窄畫面按兩欄排列，原因獨占一列。
- 只調整排列，欄位名稱、既有申請 API、時數推算、核准及報表規則不變。

## 主管批量代辦

1. 用主管本人個人網頁密碼登入，員工工作台 →「主管代辦」。授權方式仍參照 `docs/主管代辦操作說明.md`。
2. 上方「查看紀錄員工」採用與紙本補登相同的搜尋／部門篩選及員工卡片，但使用單選，決定日曆及明細顯示誰；不代表批量名單。選日期及請假／加班，表單直接顯示，不需先按「代申請」。午餐同樣直接在日期下方填表。
3. 表單「代辦員工」沿用紙本補登的搜尋、部門篩選、卡片勾選、已選／顯示人數、「選取顯示」及「清除」。篩選不取消已選者，「選取顯示」只追加目前顯示且可代辦者，「清除」取消包含隱藏者的全部勾選。預設只有正在查看的員工；每次限 1 至 100 位，只能選目前被明確指定給自己的員工。
4. 填相同時間、每人整筆時數、事由及必填代辦原因，勾選核准確認。例：主管有 10 位員工，可只勾 8 位送同一份加班計畫；未勾選的 2 位不建立紀錄。
5. 請假每人各建一筆「管理部複核中」，每筆仍需管理部終審；加班每人各建一筆已核准紀錄。不是把多人塞入同一筆，時數也不是所有員工的合計。
6. 午餐按同一天、同一個「用餐／不用餐」選項批量代登。未參加或本日不可修改者不能勾選；同樣受供餐、每日截止與結單限制。

整批先檢查授權、時段重疊與午餐資格。任一人有衝突、授權撤銷、資料過期或稽核寫入失敗，整批不儲存，不會只成功一半。錯誤會指出目前授權內的衝突員工；修正名單或內容後再送。

搜尋及部門篩選本身不視為未儲存的申請修改。勾選名單或編輯內容後，切換員工、日期、月份、項目／工作台，或按「重設表單」時，會先確認是否捨棄內容；按「繼續編輯」保留原名單及欄位。送出成功後重設申請表，仍保持直接顯示。

每人的紀錄保留實際操作者、代辦原因與時間；請假／加班的稽核另含共同 batchId 與筆數。午餐直接更新原員工同日紀錄，不累積取消副本。全日請假的「確認取消餐點」只勾回目前查看的該位員工，不會連帶取消其他勾選者的餐點。

## 個別員工網頁打卡權限

1. 管理者工作台 →「安全設定」→「員工網頁打卡權限」。需 `admin.security.manage`；只有查看安全設定權限的人只能看不能修改。
2. 使用與紙本補登相同的搜尋、部門篩選、卡片多選及已選人數；「選取顯示」允許目前顯示者，篩選外的勾選保持原狀，「清除」取消全名冊勾選。勾選表示允許、取消勾選表示停用，篩選隱藏不等於停用。填設定原因、勾選確認後按「儲存網頁打卡權限」才會套用。系統管理者工作台也有同名設定區；僅有查看權限者仍可搜尋及篩選，但不能勾選、批選或儲存。
3. 停用後仍能登入員工工作台、請假、加班、團膳及依原授權代辦；打卡按鈕顯示「未開放網頁打卡」。後端每次送出重新檢查，舊登入 Token 或直接呼叫網頁打卡 API 也不能繞過，拒絕時不建立打卡。
4. 只限制 `/api/browser/punch`；實體卡打卡、外部卡號 API 及管理者補登維持原權限與安全規則。允許網頁打卡也仍須符合原裝置綁定／GPS 規則。

升級前所有員工均可線上打卡，因此升級後及未另外設定的新員工預設仍允許，避免突然封鎖既有使用者。管理者需按公司政策逐一取消不允許者。刪除員工會清除其打卡例外，重用工號不繼承舊例外；新員工加入時請重新確認政策。

多人同時設定或名冊變更，舊版本儲存會拒絕，請重新整理後重選。設定的前後內容、實際操作者、時間及原因會寫入稽核；稽核失敗整批回滾。

## 共用主管設定

- 管理者工作台 →「主管指定」改為側邊「主管審核」及「代辦主管」，系統管理者也使用相同子頁面。切換未儲存內容會先確認。
- v1.24.0 審核改為每位員工指定一位主管，請假／加班共用，可跨部門、可多選員工批量設定；部門僅用於名單篩選。升級將當時部門路徑轉為個人指定，但不重新指定歷史案件的審核人。詳見 `docs/主管審核個別指定說明.md`。
- 共用路徑沿用 `admin.leave.settings`，也仍能設定請假假別。只持有該權限者會看到「主管指定」及共用路徑，但不能修改代辦授權；代辦指定需另有 `admin.supervisors.manage`。
- 審核是一員工一主管；指定代辦主管是一員工一或多位。兩種用途不同，不互相自動授權。只有代辦指定權限者不能修改共用審核主管。
- 「設定主管的員工」及「指定的代辦主管」皆為卡片多選，均可搜尋／部門篩選、「選取顯示」及「清除」，各自有選取計數與高度控制。初始不預選；員工與主管不能包含同一人，避免指定本人。
- 新頁面使用 `/api/browser/supervisors/reviewers/batch`，檢查每人版本及整份名冊，稽核保留每人前後指定與原因。首次個別儲存後，舊部門寫入 API 拒絕覆蓋。

## 批量指定代辦主管

1. 多選「設定主管的員工」（1 至 100 位），再多選「指定的代辦主管」（最多 100 位）；例如選 8 位員工及 2 位主管。兩區的搜尋／部門篩選獨立，篩選不清除勾選。「清除」只清勾選，不會立即變更已存授權。
2. 預設「新增主管（保留原指定）」：每位員工原有主管仍在，再加入本次所選主管，不產生重複關係，也不修改原關係的時間或操作者。至少選 1 位主管。
3. 「取代主管（改為本次勾選）」：所選員工的全部主管改成這份名單，未勾選的原主管會被移除。只改所選員工，下方表格保留現有指定可供核對。
4. 若要撤銷所選員工全部代辦授權：選取代模式、清除主管勾選，額外勾「確認清除所有勾選員工的全部代辦主管授權」，再依下一步儲存。更動員工、主管或模式會取消清除確認，需重新確認。
5. 填設定原因、勾「確認依所選模式更新所有勾選員工的代辦主管授權」，按「批量儲存主管指定」。模式、原因、確認與儲存按鈕在寬螢幕同列，手機換行；額外清除確認另列。每位所選員工套用同份主管名單；未選員工不變。員工與主管名單若重疊，先取消重疊者或拆批設定。
6. 儲存前檢查所有員工各自的 revision、名冊、主管資格、模式、原因及確認。同一 SQLite transaction 完成所有授權與稽核；任一人資料過期、名冊變更或稽核失敗，整批不儲存。重新整理取得新資料後再設定，沒有強制覆蓋選項。
7. 每位員工保留修改前後主管、模式、原因、實際操作者與時間；共同 batchId、batchSize 可追查整批。設定權限仍為系統管理者或 `admin.supervisors.manage`，不影響個別審核主管、原申請或營運歷史。
8. 編輯時收到其他連線的主管／名冊異動，畫面保留未儲存勾選與原因並提示。再儲存會使用原 revision 檢查過期，不會靜默覆蓋；重新整理或切換前仍有捨棄確認。

網頁使用新增 `/api/browser/supervisors/assignments/batch`，送出 employeeIds、supervisorIds、mode、各員工 revisions、reason、confirmAssignment；空白取代另需 confirmClear。舊單員工 `/api/browser/supervisors/assignments` 保持相容。

## 升級與備份

新增 `browser_punch_permissions` 表，既有員工、請假、加班、打卡、部門路徑與團膳訂餐快照不重建、不重算。完整 SQLite 備份含此表；舊備份啟動時自動建立空表，維持預設允許。核心資產備份含新模組、測試與本說明，不上傳實際資料庫或帳密金鑰。

停用權限開始使用後，不可直接降回 v1.20.0 或更舊程式：舊版不認識新權限表，會恢復所有員工網頁打卡。若必須降版，先停用網頁服務並由管理者另行控管。

v1.21.1 只共用員工選取介面與直接顯示既有表單，不新增或搬移資料表、不改寫既有紀錄及授權，不更改後端 API 或審核／截止規則。

v1.21.2 只修正全寬排版與增加名單高度控制，不變更資料結構、既有資料或 API 欄位；權限驗證、紙本同筆修正及未儲存內容保護保留。

v1.22.0 新增批量指定 API 與操作，不新增資料表、不重建既有授權；舊單人 API 與共用部門審核路徑保持相容。

v1.24.0 的個別審核遷移、權限、備份與降版風險參照 `docs/主管審核個別指定說明.md`。

依 `docs/更新紀錄.md`、`docs/快速部署還原說明.md`、完整使用手冊執行同步、備份、版本、測試、建置、commit 及 push。真正打卡鐘主機更新並重啟後，核對 `/api/browser/health` 的 `data.appVersion` 是 1.24.0；GitHub push 不代表主機已部署。
