# 工作台批量代辦與網頁打卡權限

日期：2026-10-05；適用版本：v1.21.1。

## 員工申請表

- 請假申請、加班申請：電腦版第一列為開始日期／開始時間／結束日期／結束時間；第二列為假別或加班員工／每人時數／原因。較窄畫面按兩欄排列，原因獨占一列。
- 只調整排列，欄位名稱、既有申請 API、時數推算、核准及報表規則不變。

## 主管批量代辦

1. 用主管本人個人網頁密碼登入，員工工作台 →「主管代辦」。授權方式仍參照 `docs/主管代辦操作說明.md`。
2. 上方「查看紀錄員工」採用與紙本補登相同的搜尋／部門篩選及員工卡片，但使用單選，決定日曆及明細顯示誰；不代表批量名單。選日期及請假／加班，表單直接顯示，不需先按「代申請」。午餐同樣直接在日期下方填表。
3. 表單「代辦員工」沿用紙本補登的搜尋、部門篩選、卡片勾選、已選／顯示人數、「選取顯示」及「清除」。篩選不取消已選者，「選取顯示」只追加目前顯示且可代辦者，「清除」取消包含隱藏者的全部勾選。預設只有正在查看的員工；每次限 1 至 100 位，只能選目前被明確指定給自己的員工。
4. 填相同時間、每人整筆時數、事由及必填代辦原因，勾選核准確認。例：主管有 10 位員工，可只勾 8 位送同一份加班計畫；未勾選的 2 位不建立紀錄。
5. 請假每人各建一筆「管理部複核中」，每筆仍需管理部終審；加班每人各建一筆已核准紀錄。不是把多人塞入同一筆，時數也不是所有員工的合計。
6. 午餐按同一天、同一個「用餐／不用餐」選項批量代登。未參加或本日不可修改者不能勾選；同樣受供餐、每日截止與結單限制。

整批先檢查授權、時段重疊與午餐資格。任一人有衝突、授權撤銷、資料過期或稽核寫入失敗，整批不儲存，不會只成功一半。錯誤會指出目前授權內的衝突員工；修正名單或內容後再送。

搜尋及部門篩選本身不視為未儲存的申請修改。勾選名單或編輯內容後，切換員工、日期、月份、項目／工作台，或按「重設表單」時，會先確認是否捨棄內容；按「繼續編輯」保留原名單及欄位。送出成功後重設申請表，仍保持直接顯示。

每人的紀錄保留實際操作者、代辦原因與時間；請假／加班的稽核另含共同 batchId 與筆數。午餐直接更新原員工同日紀錄，不累積取消副本。全日請假的「確認取消餐點」只勾回目前查看的該位員工，不會連帶取消其他勾選者的餐點。

## 個別員工網頁打卡權限

1. 管理者工作台 →「安全設定」→「員工網頁打卡權限」。需 `admin.security.manage`；只有查看安全設定權限的人只能看不能修改。
2. 使用與紙本補登相同的搜尋、部門篩選、卡片多選及已選人數；「選取顯示」允許目前顯示者，篩選外的勾選保持原狀，「清除」取消全名冊勾選。勾選表示允許、取消勾選表示停用，篩選隱藏不等於停用。填設定原因、勾選確認後按「儲存網頁打卡權限」才會套用。系統管理者工作台也有同名設定區；僅有查看權限者仍可搜尋及篩選，但不能勾選、批選或儲存。
3. 停用後仍能登入員工工作台、請假、加班、團膳及依原授權代辦；打卡按鈕顯示「未開放網頁打卡」。後端每次送出重新檢查，舊登入 Token 或直接呼叫網頁打卡 API 也不能繞過，拒絕時不建立打卡。
4. 只限制 `/api/browser/punch`；實體卡打卡、外部卡號 API 及管理者補登維持原權限與安全規則。允許網頁打卡也仍須符合原裝置綁定／GPS 規則。

升級前所有員工均可線上打卡，因此升級後及未另外設定的新員工預設仍允許，避免突然封鎖既有使用者。管理者需按公司政策逐一取消不允許者。刪除員工會清除其打卡例外，重用工號不繼承舊例外；新員工加入時請重新確認政策。

多人同時設定或名冊變更，舊版本儲存會拒絕，請重新整理後重選。設定的前後內容、實際操作者、時間及原因會寫入稽核；稽核失敗整批回滾。

## 共用主管設定

- 管理者工作台 →「主管指定」上方為「請假／加班共用主管審核路徑」，下方為「指定代辦主管」。系統管理者也提供這兩區。
- 部門審核路徑確實同時用於員工自行申請請假、加班及原部門主管代申請；舊版只是將入口放在請假管理。這次搬移入口，不搬資料、不重新指定歷史案件的審核人。
- 共用路徑沿用 `admin.leave.settings`，也仍能設定請假假別。只持有該權限者會看到「主管指定」及共用路徑，但不能修改代辦授權；代辦指定需另有 `admin.supervisors.manage`。
- 部門路徑是一部門一主管（或預設 *）；指定代辦主管是每位員工一或多位、可跨部門。兩種用途不同，不互相自動授權。只有代辦指定權限者不能修改共用路徑。
- 「設定主管的員工」以搜尋／部門篩選卡片單選一位員工，下方「該員工的代辦主管」以相同介面多選，可「選取顯示」或「清除」；本人不在主管候選名單。仍逐員工設定，不將上方單選改成多人批量授權，勾選後需填原因、確認及儲存才生效。
- 舊 `/api/browser/admin/leave-routes/save` 保持相容，新頁面使用 `/api/browser/supervisors/routes` 並檢查版本，稽核包含修改前後完整路徑。

## 升級與備份

新增 `browser_punch_permissions` 表，既有員工、請假、加班、打卡、部門路徑與團膳訂餐快照不重建、不重算。完整 SQLite 備份含此表；舊備份啟動時自動建立空表，維持預設允許。核心資產備份含新模組、測試與本說明，不上傳實際資料庫或帳密金鑰。

停用權限開始使用後，不可直接降回 v1.20.0 或更舊程式：舊版不認識新權限表，會恢復所有員工網頁打卡。若必須降版，先停用網頁服務並由管理者另行控管。

v1.21.1 只共用員工選取介面與直接顯示既有表單，不新增或搬移資料表、不改寫既有紀錄及授權，不更改後端 API 或審核／截止規則。

依 `docs/更新紀錄.md`、`docs/快速部署還原說明.md`、完整使用手冊執行同步、備份、版本、測試、建置、commit 及 push。真正打卡鐘主機更新並重啟後，核對 `/api/browser/health` 的 `data.appVersion` 是 1.21.1；GitHub push 不代表主機已部署。
