# 個別員工主管審核指定

日期：2026-10-17；適用版本：v1.28.0。

## 設定入口

管理者工作台 →「主管指定」→ 側邊「主管審核」。系統管理者也有相同兩個子頁面。

1. 多選「設定審核主管的員工」（1 至 100 位），再多選「指定的審核主管」（最多 100 位）。可搜尋、按部門篩選及調整名單高度；部門僅用於篩選，不決定審核主管。
2. 選「任一位核准即可」，或「指定必審主管皆需核准」並從已選主管再勾必審者。其他指定主管也可審核，但不能取代必審者；案件尚待主管審核時，任一指定主管駁回即退回整單。每位主管只審一次，已完成主管階段後不能再補投駁回。同部門可有不同規則，也可跨部門指定；本人不能審核自己。
3. 填設定原因，勾更新確認，按「批量儲存審核主管」。只更新勾選員工，其他人不變；下方表格顯示目前已存指定。
4. 清除審核主管：選員工，在主管名單按「清除」，另勾「確認清除所選員工的審核主管」，再填原因、勾更新確認並儲存。清除選取本身不改營運設定。
5. 未指定主管的員工不能自行送出請假／加班，會提示聯絡管理者設定。新員工不按部門自動繼承；已指定員工調部門也不自動改派。

「代辦主管」子頁面保留多選員工及多選主管，使用新增／取代模式。設定模式、原因、更新確認與儲存按鈕在寬螢幕同一列；窄螢幕及手機換行。額外清除授權確認另列，不省略。切換子頁面及重新整理時有未儲存內容確認，繼續編輯會保留草稿。

## 權限與流程

- 主管審核設定沿用 `admin.leave.settings`；代辦授權仍需 `admin.supervisors.manage`。只有其中一種權限，只顯示該子頁面；身份模擬拒絕設定。指定主管不自動開通管理者角色或主管代辦授權。
- 新的員工請假先送其指定主管，再送管理部終審；本人加班先送指定主管核准。員工工作台「主管審核」專門查看及審核請假／加班待審。審核主管不能再由本人加班申請入口替別人送件；代送統一由獨立代辦授權辦理，詳見 `docs/主管代辦操作說明.md`。
- 改派只影響之後建立的新申請。已送出、待審、核准、駁回與歷史案件的 ID、時數、狀態、審核主管及審核步驟不改寫。舊待審案件仍由原案件主管審核，不重新派案。
- 新單送出時保存主管名單、規則與必審者快照。部分核准仍在主管階段，不送管理部、不視為加班已核准；請假額度維持待審預占。紀錄與日曆明細可展開每人決定、意見與必審進度。主管員工工作台上方「待我審核」顯示本人尚未審核的請假／加班總筆數，按鈕直達相應待審頁。
- 多主管或指定必審的主管代申請仍要依同一快照送審，不能由代辦授權繞過必審；原單主管且任一核准模式的代辦流程保留。紙本已核准補登仍依獨立管理權限辦理，不變更原單 ID。
- 每位員工的 revision 及整份名冊都須相符。整批指定與每人前後稽核在同一 SQLite transaction；任一員工資料過期、員工／主管不存在、指定本人或稽核失敗，整批不寫入。稽核含原因、實際操作者、時間與共同 batchId。

## 升級、備份與相容

- 新增 `employee_review_supervisors`，既有 `leave_approval_routes` 保留作為舊設定資料。首次升級只將當時現有員工的有效部門路徑（含預設路徑）轉為明確個人指定，保留原部門／預設優先規則，不重複遷移。本人或不存在的主管不轉入，畫面顯示未指定，需管理者補設定。
- 轉換及遷移稽核保持同一交易；失敗停止，不能留下半套指定。政策、遷移標記與指定隨完整 SQLite 備份還原，刪除員工／主管會清除相應指定，重用工號不繼承舊指定；不刪除歷史申請。
- 網頁 API：GET `/api/browser/supervisors/reviewers`；POST `/api/browser/supervisors/reviewers/batch`。送出 employeeIds、supervisorIds、mode（any／required）、requiredSupervisorIds、revisions、reason、confirmReview；清空另需 confirmClear。保留舊單一 supervisorId 欄位相容。
- v1.27.0 增加 `employee_review_policies`、`employee_review_members`、`request_review_policies`、`request_review_votes`、`request_review_epochs`。舊單主管設定沿用，不為舊案件補寫或重算快照。刪除主管後停用其原票權，重用工號不繼承；缺少必審主管時必須重新設定未來規則，歷史未完成案件不自動跳過必審者，也不自動改派。
- 舊部門設定 API 僅在尚未使用個別指定儲存前保留相容，將當時名冊轉為個人指定，不對未來新員工生效；首次個別儲存後，舊部門寫入回應 409，避免舊頁面覆蓋個人設定。請重新載入新網頁。
- 更新前先備份真正打卡鐘主機的完整 SQLite 與 WebCredentials。不得直接降至 v1.23.0 或更舊版本：舊版會忽略個人指定並讀舊部門設定，可能錯派案件。如必須降版，先停止網頁服務，評估並還原升級前完整備份。
- 核心資產備份含新模組與文件／測試，不加入實際資料庫、log 或金鑰到 Git。GitHub push 不等於正式主機部署；更新並重啟後確認 `/api/browser/health` 版本 1.28.0，再重新載入網頁。不可降版後繼續審核多主管新單，舊版忽略必審票權；必要回復時停機並還原升級前完整備份。
