# 工作台指標與多主管審核

日期：2026-10-16；適用版本：v1.27.0。

## 八張管理指標

管理者工作台上方固定一排八個位置，右上齒輪「設定八張指標」可選指標及順序，勾確認後儲存。選到另一位置已有的指標會交換位置。設定依個人帳號保存，不會改其他管理者；關閉未儲存設定會詢問是否捨棄。電腦寬螢幕一次顯示八張，窄螢幕與手機維持一排橫向捲動。

預設：員工數量、今日正常打卡、今日請假人數、今日加班人數、請假待主管審核、請假待管理部複核、加班待主管審核、今天午餐份數。原班別、異常打卡、響鈴、問候語及主題仍可自行選回，共 27 個指標選項。

- 請假／加班各有今天前 3 天、今天、後 3 天，共 7 個逐日指標，依台北時間跨月／跨年更新。各日只計已核准、同一員工不重複計人；請假若有每日實際時數，僅計有正時數的日期，舊單沒有分配則按起訖區間判定，結束時間不含在區間內。
- 待主管審核及待管理部複核計「申請單數」，涵蓋全部日期，不受最近 100 筆列表或員工本人歷史可見月數限制；一張多主管單仍只計一單。
- 今天／明天午餐計目前預訂份數，副標分別標示供餐狀態與已交給供應商的份數；未交單不等於零份。參加午餐團膳人數依今日生效參加資格，不等於今日用餐數。登記不等於領餐或餐費。
- 點新指標可看明細，每頁 50 筆；人數卡片的多筆申請仍逐單列出，故明細筆數可能大於人數。重新整理儀表板時同步更新已開明細，跨日舊日期拒絕查詢並要求重新整理。
- 指標、明細與設定皆驗證目前權限；失去權限會改填其他可用指標，權限少於八項時保留空白位置，不洩漏未授權數值。身份模擬不能儲存個人設定。

## 原本的監測

原本員工數量彈窗的「監測」是正常／異常打卡的人員統計範圍，不是監視員工，也不會限制打卡或更改員工權限。v1.27.0 改名「出勤統計範圍」，移到正常／異常打卡明細內。員工數量改為真正名冊總數及在職／離職概況，不再跟著出勤篩選縮小。出勤範圍仍是原瀏覽器的顯示偏好，不影響請假、加班或團膳統計。

## 多主管與主管提示

在「主管指定 → 主管審核」多選員工與主管，再選任一核准或指定必審，詳細步驟、代辦例外與升降版風險參照 `docs/主管審核個別指定說明.md`。審核授權不等於代辦授權。

主管以本人帳號進員工工作台，上方顯示「待我審核」及請假／加班分項，可直接進對應審核日曆。只計此人尚有票權且尚未決定的案件；部分核准後其他必審者仍看得到。舊單保留原主管，不依新設定改派。

## 備份與部署

新增個人指標設定表 `dashboard_metric_preferences`，隨完整 SQLite 備份保存；刪除員工後清除其顯示偏好，重用工號不繼承。多主管規則與個案票權表也在原 SQLite，不改既有申請、時數或紙本修正方式。來源備份腳本包含新後端模組、前端、測試與文件。

遵守 `docs/更新紀錄.md` 與 `docs/快速部署還原說明.md`，升級前備份真正服務主機完整 SQLite 與 WebCredentials。GitHub push 不等於部署；更新並重啟服務，驗證 `/api/browser/health` 的 `data.appVersion` 為 1.27.0，再重新載入瀏覽器。
