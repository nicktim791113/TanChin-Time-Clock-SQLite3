# 快速部署還原說明

這份文件放在核心資產備份壓縮檔內，用來在新電腦、重灌後或資料搬移時快速恢復 TanChin-Time-Clock-SQLite3。

## 備份檔內容結構

解壓縮核心資產備份檔後，主要會看到：

```text
backup-manifest.json
project-source\
runtime-user-data\
```

- `project-source`：專案原始碼、開發文件、文案、備份腳本。
- `runtime-user-data`：實際營運資料，例如 `app_data.db`、自訂音效、主題圖片、LOG。
- `backup-manifest.json`：本次備份的來源、時間、包含項目與缺漏項目。

## 情境一：只把資料恢復到已安裝的軟體

### v1.18.0 午餐團膳

- 團膳五張資料表直接存在原本的 SQLite，完整資料庫備份包含制度、參加資格、每日例外與各版供應商交單快照；舊備份還原後自動建立空團膳表，不需另外搬檔。
- 核心資產 ZIP 已包含 `meal-management.js`、`meal-routes.js`、瀏覽器團膳頁、測試與 `docs/午餐團膳操作說明.md`。
- 首次部署由團膳管理者設定供餐星期、每日截止與參加資格，沒有預設供餐星期或測試員工。既有員工卡號可直接使用員工團膳月曆。
- 更新服務主機後須重新啟動；GitHub push 不會自動更新其他主機的正在執行服務。本次只有網頁員工／管理者操作頁，桌面啟動同一資料庫與網頁服務。
- 訂餐快照不等於實際領餐；交單按鈕是記錄已完成的外部通知，不會自動傳送給供應商。

### v1.17.0 個人網頁密碼與金鑰

- 網頁一般登入改用工號與卡號或個人網頁密碼。既有員工卡號不變，卡號登入只進員工工作台。
- 網頁管理者／開發人員首次部署後，先由獨立系統管理者登入，授權角色並於「個人網頁密碼管理」設定臨時密碼；本人首次登入須修改，再重新登入選擇工作台。舊桌面共用密碼不可再用來登入網頁管理工作台。
- 個人網頁密碼以 scrypt 雜湊驗證，並以 AES-256-GCM 加密保存目前密碼，金鑰放在營運資料庫同層的 `WebCredentials/keyring.json`。不可刪除或上傳 GitHub。
- 恢復核心資產 ZIP 時，須連同 `runtime-user-data/WebCredentials` 搬移到營運資料資料夾。只搬移專案原始碼不會搬移帳號密碼或金鑰。
- 軟體內的完整資料庫備份會另存 `<備份檔名>.db.web-credentials.json`；需與 `.db`、`.manifest.json` 一起保留。還原會合併金鑰，保留目前資料與緊急備份所需的金鑰；缺少所需金鑰即停止，不覆蓋資料庫。
- 尚未有個人網頁密碼的舊備份仍可還原。金鑰遺失時，雜湊驗證仍可登入，但無法查回該密碼；由系統管理者重設可建立新金鑰。原有密碼不可憑空復原。
- 金鑰備份可解密個人密碼，請限權保管，不要放在公開分享路徑。正式跨網路部署使用 HTTPS 或受控 VPN；HTTP 即使資料庫加密也不保護傳輸。
- 系統管理者帳密仍獨立。桌面共用管理者／開發人員密碼仍能於相應網頁設定表單修改，與個人網頁密碼分開。

適合情況：

- 你已經安裝好 TanChin-Time-Clock-SQLite3。
- 只想把員工資料、打卡資料、自訂音效、主題圖、設定資料恢復回來。

步驟：

1. 關閉打卡軟體。
2. 解壓縮備份 zip。
3. 複製備份檔內的：

```text
runtime-user-data\*
```

4. 貼到並覆蓋：

```text
%APPDATA%\TanChin-Time-Clock-SQLite3
```

通常完整路徑是：

```text
C:\Users\你的使用者名稱\AppData\Roaming\TanChin-Time-Clock-SQLite3
```

5. 重新開啟打卡軟體。

檢查重點：

- 員工資料是否存在。
- 打卡紀錄是否存在。
- 自訂音效與主題圖片是否能正常顯示或播放。
- 管理者/開發人員工作台是否能登入。

## 情境二：恢復成可開發或可重新打包的專案

適合情況：

- 換電腦後要繼續開發。
- 要重新打包安裝檔。
- 要把原始碼完整搬到另一個資料夾。

步驟：

1. 解壓縮備份 zip。
2. 建立或選擇你的專案資料夾，例如：

```text
C:\Users\你的使用者名稱\Desktop\Developer\TanChin-Time-Clock-SQLite3
```

3. 把備份檔內的：

```text
project-source\*
```

複製到專案資料夾。

4. 在專案資料夾執行：

```powershell
npm install
```

5. 啟動開發版：

```powershell
npm start
```

6. 需要重新產生安裝檔時執行：

```powershell
npm run build
```

注意：

- 備份檔不包含 `node_modules`，所以新環境要先跑 `npm install`。
- 備份檔不包含 `dist`，因為打包輸出可以重新產生。
- 如果是全新電腦，需要先安裝 Node.js。

## 快速備份指令是否只能在這台電腦使用？

不是只能在這台電腦使用，但它主要是為 Windows + 這個 Electron 專案設計。

這支指令可以在同一個專案的其他 Windows 電腦使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\scripts\backup-core-assets.ps1"
```

腳本會自動判斷：

- 專案來源：以 `scripts\backup-core-assets.ps1` 所在位置往上一層作為專案根目錄。
- 軟體營運資料：預設讀取 `%APPDATA%\TanChin-Time-Clock-SQLite3`。
- 備份輸出位置：預設輸出到目前 Windows 使用者底下的 OneDrive 路徑。

如果另一台電腦的 OneDrive 路徑不同，請改用自訂輸出位置：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\scripts\backup-core-assets.ps1" -DestinationRoot "D:\TanChin-Time-Clock-SQLite3 原始資料備份"
```

如果另一台電腦的軟體資料夾不同，請指定 `UserDataPath`：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\scripts\backup-core-assets.ps1" -UserDataPath "C:\Users\你的使用者名稱\AppData\Roaming\TanChin-Time-Clock-SQLite3"
```

也可以兩個都指定：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\scripts\backup-core-assets.ps1" -DestinationRoot "D:\備份\TanChin" -UserDataPath "C:\Users\你的使用者名稱\AppData\Roaming\TanChin-Time-Clock-SQLite3"
```

## 建議還原前先做一件事

如果目標電腦已經有舊資料，還原前先把這個資料夾整個複製一份保存：

```text
%APPDATA%\TanChin-Time-Clock-SQLite3
```

這樣如果覆蓋錯資料，還可以退回原本狀態。
