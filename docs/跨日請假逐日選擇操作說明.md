# 多日期、多時段與既有逐日請假操作說明

更新日期：2026-10-23。適用版本：v1.37.0。既有逐日模式自 v1.31.0 提供，多日期、多時段整單申請自 v1.34.0 提供；v1.36.0 將員工本人入口整合為「我的請假」，v1.37.0 新增獨立休息分鐘及預設時間調整。

## 新申請的處理方式

同一假別可以把分開的日期、數個日期區間，以及同一天不重疊的上午／下午時段，放進一張申請單。每段都有自己的日期、開始、結束、休息分鐘與扣除休息後的實際時數；日期之間及同日時段之間的空檔不算請假。

整張單只有一個單號與一套審核流程。主管核准／駁回針對整張單；管理部終審仍按原流程處理。不同假別請分單；本次沒有逐段核准或部分撤回功能。

適用入口：員工本人請假、管理者紙本核准請假補登、原紙本修正、授權主管單筆及批量代辦。多人代辦共用同一份時段清單，但每位員工各建立一張申請，仍受各自的指定主管、必審規則及代辦範圍限制。加班仍使用單一連續起訖，不採請假多段資料模式。

## 員工本人：日曆選日（v1.36）

從員工工作台「我的請假」同頁完成申請與查紀錄。按「新增申請」後選同一假別與實際日期，可選不連續日期、套用共用時段，再逐段調整或新增同日另一段。填事由、核對每段扣除休息後的時數及整張摘要，再送出；申請與紀錄不必來回換入口。

員工新草稿預設 08:20–17:00，完整涵蓋 12:20–13:00 時帶入休息 40 分鐘及淨時數 8 小時；其他時段預帶休息 0 分鐘，部分涵蓋午休也請自行填實際休息。休息以整數分鐘輸入，修改後重算淨時數。手動休息與手動淨時數在改起訖後保留；要回復輔助計算，按「恢復自動休息與時數」。

日曆瀏覽模式點日期只查紀錄，不會建立申請。手機選日後進入全高編輯面板，底部核對總時數與送出。請假草稿在本次登入期間切換月份／頁面仍可接續；重整、關頁或登出後不保存。完整說明見 [請假與加班日曆操作說明](請假與加班日曆操作說明.md)。

以下「新增日期或區間」的上方區間加入方式保留於主管代辦、管理者補登／修正等原入口；員工新版以日曆選日與同頁編輯代替，但下列時段、歷史單、扣假及審核規則一致。

## 新增日期或區間

1. 選員工（本人入口不需選）、一種假別及請假原因。
2. 在「新增區間開始日期／結束日期」填入要加入的日期範圍，開始與結束同日表示加入一日。上方「每日開始時間／每日結束時間」會套用到這個區間的每一天。
3. 在「每日休息（分鐘）」核對休息，並核對「加入區間的每日時數」，再按「加入上方日期區間」。紙本補登預設 08:20～17:00，完整涵蓋 12:20～13:00 時預帶 40 分鐘，扣除後 8 小時；其他時段預帶 0 分鐘，可自行調整。修改休息會重算淨時數；手動值在改時間後保留，可按「恢復自動計算」重算。
4. 多日區間預設只加入週一至五。需含週末時勾「多日區間包含週末」；單日直接加入所選日，即使是週末。這只是輸入便利預設，系統沒有公司排班及完整國定假日資料，請自行刪除不需請假的日期並核對補班日。
5. 再更改上方日期／時間、填每日時數並按加入，可把其他日期區間接到同一張單。更改上方輸入不會更動已加入清單；清單中的各段才是將要送出的內容。
6. 只需一段時可按「新增單一時段」，直接在該列改日期、起訖及實際時數。按「同日加一段」會沿用日期，新增一列供填寫另一個時段；新列的結束時間及時數須自行填寫。
7. 核對全部時段與「幾日、幾段、合計幾小時」。紙本補登另填核准依據，主管代辦另填代辦原因。按原表單送件按鈕，一次送出整張單。

例如同一假別的 11/3 09:00～11:00（2 小時）、11/3 14:00～16:00（2 小時），以及 11/10 13:00～17:00（4 小時），會合為一張 2 日、3 段、8 小時的申請。11/3 中間的空檔與 11/4～11/9 不算請假。

## 時段規則與欄位

| 項目 | 用途或限制 |
| --- | --- |
| 新增區間日期／每日起訖 | 只供加入清單使用；不會把已加入清單外的日期當成請假。 |
| 各段日期、開始、結束 | 每段在同一台北日期內。同一日可有多段，不能重疊；前段結束等於後段開始可以。 |
| 結束 00:00 | 表示該日 24:00。例如 12/31 22:00～00:00 只算 12/31；跨夜至 1/1 02:00 請另新增 1/1 00:00～02:00。 |
| 各段休息分鐘 | 可另填 0 以上整數，須小於該段起訖分鐘；完整涵蓋 12:20～13:00 預帶 40，否則預帶 0。修改此欄會重算淨時數。舊單未記錄者保留空值，不推測補填。 |
| 各段實際時數 | 必填正數，最多兩位小數，不超過該段起訖差值扣除休息後的時間或 24 小時；可再人工調整。扣假及報表使用此淨時數，不再扣一次休息。 |
| 同日加一段 | 新增同日的另一個時段；須填完整時間與時數，不會複製原段識別碼。 |
| 刪除 | 從目前草稿清單移除此段。舊紙本修正須按整份修正儲存才生效。 |
| 合計時數 | 唯讀；按各段實際時數加總，後端會重新核算。同日多段另彙總為每日扣抵。 |
| 長度限制 | 每張最多 740 段；最早至最晚日期最多跨 370 個日期。超過請分單。 |
| 明細展開 | 審核、紀錄、日曆及管理畫面可展開各段日期、起訖及時數，避免只看最早／最晚外框。 |

加入重複或重疊的區間會被拒絕；已建立的合法清單不會因加入失敗而部分新增。編輯中的缺漏、重疊或超額時數須修正後才能送件。

## 下游資料與審核

- 額度及精確年資帳按各實際日期的加總時數扣抵／預占，跨年使用該日期適用年度與來源。
- 日曆與每日人數統計只計有時段的日期。同一天同一張單有兩段，仍是一張單，不重複計為兩位員工。
- 重複申請檢查依實際時段；日期或時段間的空檔不會被外層最早／最晚起訖擋住。
- 考勤請假明細保留各段起訖、段落時數與整張單號。串接方應使用實際段落與穩定識別碼，不可自行把外框期間補成連續請假。
- 午餐請假提醒依實際同日時段及時數核對；提醒仍須按既有團膳規則人工確認，不是直接替員工取消餐點。
- 管理者請假出勤查核：距實際連續請假區塊的開始／結束前後 20 分鐘內（含邊界）顯示黃色「容許時間範圍」；更深的區間內打卡仍為紅色衝突。真實空檔不列請假，相接段落與歷史午夜切點不新增容許邊界；全天區間外打卡與部分請假無打卡的獨立提醒保留。
- 一次審核整張單；待審撤回、駁回及紙本作廢依原權限與狀態處理整份時數。多人代辦任一人無權限、有衝突或寫入失敗時，整批不寫入。
- 紙本修正保留同一申請單號，時段、每日扣抵及操作紀錄一起保存。已有時段識別碼只能用於原單，新增段落由伺服器另配識別碼。

## 既有逐日單與歷史連續單

升級不會自動把歷史單換成多時段，也不會推測上午／下午、刪除週末或重算已核准時數。

修正既有 explicit_dates 逐日紙本單時，仍顯示原逐日勾選介面，回填原日期與每日時數。第一／最後日按原外框限制，中間日仍是整個日期範圍；每日時數只代表扣假量，不能推測確切時段。舊逐日單不能直接降回連續區間。

修正 legacy_range 歷史連續紙本單時，仍提示重新勾選並填每日實際時數；確認儲存後才轉為逐日模式。歷史「每日扣抵分配」只是帳務資料，不能用來推定原來沒有請假的日期。

新 explicit_segments 多時段紙本單修正時會帶回各段的精確起訖與時數，不能降回逐日或連續區間。一般線上核准單的修改權限沒有擴大，請依原撤回／審核及重新申請流程處理。既有逐日或多時段單均不能從額度的舊單分配工具改寫請假日期。

v1.37.0 以前的多段單未保存休息分鐘時，顯示「舊單未記錄」，保持原淨時數；升級、開啟修正或只改事由都不會推測休息或再次扣時數。明確修改休息或使用「恢復自動計算」後，才依輸入重算該段並在儲存時保留休息資料。修正原單仍須核對全部日期、時數及修改原因。

## 備份與部署

精確時段另存於資料庫，並與原申請、每日扣抵及操作紀錄同交易保存。完整 SQLite 備份包含全部時段；升級前備份實際主機資料庫與 WebCredentials，安裝重啟後核對發布版本，再重新整理網頁。

v1.37.0 為段落新增可為空值的 `break_minutes`；原列保持空值及原時數，新填休息與淨時數一同保存。安裝重啟後核對 `/api/browser/health` 的 `data.appVersion` 為 `1.37.0`；建置或 GitHub 推送不代表 TC-150 已部署。

舊版程式不認識新多時段模式，不可直接降版後繼續操作新資料。需要回復時停止服務、還原升級前完整備份並核對升級後異動。發布與同步遵循 [GitHub 同步與版本更新規範](GitHub同步與版本更新規範.md)；GitHub push 不代表正式主機已安裝。
