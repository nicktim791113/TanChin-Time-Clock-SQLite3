# 跨日請假逐日選擇操作說明

更新日期：2026-10-19；適用版本：v1.31.0 起。

## 這次解決的問題

起訖日期是申請範圍，範圍中間可以有不請假的日期。新版用「勾選的日期＋每日實際時數」決定請假內容，不再將所有跨過的日期直接當成請假日。同一張單保留一個單號、一套審核流程，不需要為了跳過週末拆成數張單。

適用入口：員工本人請假、管理者紙本核准請假補登、原紙本修正、授權主管單筆及批量代辦。加班仍使用原本的時間／時數表單。

## 操作步驟

1. 選員工（本人入口不需選）、假別及開始／結束日期時間。
2. 查看逐日清單。跨日預選週一至五，週六日預設不勾；單日申請會選取該日，即使是週末。這只是方便填寫的預設，不代表公司的實際排班。
3. 國定假日、排休日或其他不需請假的日期取消勾選；週末輪班、補班或實際需請假的日期可勾回。系統沒有公司排班／國定假日資料，不會自動判斷所有休假日。
4. 在每個勾選日填入扣除午休、休息等不需請假的「實際時數」。每日時數起初留白，不自動把整日或起訖差值當成請假時數。相同時數可先輸入，再按套用按鈕一次填入勾選日期。
5. 核對「已選幾日、排除幾日、合計幾小時」。總時數由每日加總，不能另外手改總數。未選日的時數不計入。
6. 填請假原因；補登另填原紙本依據，代辦另填代辦原因並確認核准。依原送件按鈕送出，權限與審核流程保持原樣。

範例：星期五至下週一，實際只有星期五及星期一各請 8 小時，則勾選這兩日、各填 8，總計 16 小時，星期六日不列請假。如果星期六也是需請假的輪班日，再勾選星期六並填實際時數。

## 欄位與按鈕

| 項目 | 用途 |
| --- | --- |
| 開始／結束日期時間 | 定義申請範圍；結束必須晚於開始，一次最多涵蓋 370 個日期。 |
| 每日勾選框 | 勾選表示當日請假；取消表示不請假、不扣該日額度。至少選一日。 |
| 星期／週末標示 | 提醒核對排班，不是國定假日判定。 |
| 每日範圍 | 顯示該日與整筆起訖的交集；第一／最後一天的可填時數受此範圍限制。 |
| 每日實際時數 | 正數、最多兩位小數、不超過該日範圍或 24 小時。請填扣除休息後的時數。 |
| 週一至五快捷 | 依星期勾選平日，週末可再手動勾回；使用後仍須核對國定假日。 |
| 全選／清除 | 選取或取消全部範圍日期；清除後不能直接送件。 |
| 套用每日時數 | 將輸入時數套用到勾選日；首末時間不足時仍須按提示改成適合的時數。 |
| 合計時數 | 唯讀；由勾選日的實際時數自動加總，後端也會重新核算。 |
| 日期明細展開 | 審核、紀錄、日曆、主管及指標明細可查看實際日期、每日時數與排除日。 |

更改起訖後，仍在範圍內的日期會保留已填選擇與時數；新增日期使用跨日預設，新增時數須填寫。單日與跨日互相切換時，會重新套用「單日勾選當日／跨日先勾週一至五」，已填時數仍保留，請再次核對勾選。若縮短時間導致某日時數超過上限，必須修正才能送出。午夜結束不多算一天，例如星期五 22:00 至星期六 00:00 只列星期五。

跨日中間日期的時間範圍是整個日期，每日時數只代表實際請假量，不表示可由系統推算午休時間或確切工作時段。同一天要分不同時段、不同假別，請各自建立有明確起訖的單日申請。

## 各功能如何一致處理

- 額度及精確年資帳只按勾選日扣抵／預占。跨年依每個實際日期使用適用年度及來源。
- 新單未勾選的日期不列入請假日曆、七日請假指標、核准請假考勤列或全日請假午餐提醒；查單日報表使用該日實際時數。
- 不請假的日期不因外層起訖範圍而擋住另一張請假單。勾選日仍依實際日期範圍檢查重複申請。
- 審核不改成每天各審一次；本人送主管／管理部、紙本補登直接已核准均沿用既有流程。主管代辦一般送管理部，多主管或必審設定仍先依指定主管規則送審。
- 紙本修正更新同一個原單 ID，日期、時數、額度及稽核一起保存；批量中任何一人無權限、有衝突或稽核失敗，整批不寫入。

## 舊紀錄與修正

更新不會自動把舊單的週末刪掉，也不重新計算已核准時數。舊單仍保留原連續區間語意；舊「每日扣抵分配」只是帳務資料，不能用它推定哪些日期當時沒有請假。

管理者修正舊紙本時會提示重新勾選並填每日實際時數，確認儲存後才轉為新版逐日模式。已有逐日資料的紙本修正會回填原選擇。新版逐日單不能改回舊模式，也不能從額度的舊單分配入口改動請假日期；應回原請假修正流程。一般線上核准單的修改權限不因這次更新而擴大，請依既有撤回／審核及重新申請流程處理。

## 備份與部署

新增日期模式欄位，沿用每日扣抵表並同交易保存。完整 SQLite 備份可保留全部選日與時數；升級前備份真正主機資料庫與 WebCredentials，安裝重啟後確認健康版本 `1.31.0`，再重新整理網頁。

舊版程式不認識排除日，不能直接降版後繼續操作新版資料。需要回復時停止服務、還原升級前完整備份並核對升級後異動。發布與同步遵循 [GitHub 同步與版本更新規範](GitHub同步與版本更新規範.md)；GitHub push 不代表正式主機已安裝。
