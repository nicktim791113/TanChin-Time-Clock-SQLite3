# 年資給假與年度結轉：設計與實作對照

日期：2026-10-17；適用版本：v1.29.0。狀態：**原草案的第一階段已實作，須先核對制度及逐人接管，再由授權人預覽確認入帳**。

檔名保留「設計草案」供既有連結使用，本文已依實際程式更新。逐項操作與完整欄位見 [自動年資給假與年度結轉操作說明](自動年資給假與年度結轉操作說明.md)。本版沒有定時自動入帳、薪資核定、付款或自動書面通知；「自動年資給假」指規則計算，確認權仍在授權人員。

## 1. 實作範圍與保留邊界

| 原規劃 | 現行結果 |
| --- | --- |
| 週年法定權利及曆年配置分開 | 已實作來源批次、完整權利快照與各年度配置，未達資格預估不入帳 |
| 保留原值或無條件進位一位 | 已實作精確有理數，分子／分母保存；同配置年度加總後只進位一次 |
| 人工額度接管 | 已實作接管日、期初未休小時、期限及對帳依據，不與舊人工額度重複加總 |
| 年資版本及異動 | 已實作生效版本；若影響既往權利，保存待核對提案、不套用並封鎖後續給假 |
| 給假、結算、精確調整 | 已實作預覽、確認、過期檢查、冪等及同交易嚴格稽核 |
| 到期遞延與離職結算 | 已實作逐來源處理，遞延需同意，已遞延及已離職者不能再遞延 |
| 員工／代辦主管查看 | 已實作本人或明確授權員工的已入帳快照，排除年資／同意證據 |
| 薪資核定與付款 | 未實作；只有 `wage_pending` 待未休工資處理記錄，不能標示已付款 |
| 背景排程自動發給／自動結轉 | 未實作；年資到期或跨年不會直接改額度 |
| 特殊歷史資料一鍵回寫 | 未提供；專用歷史／政策對帳仍需另處理，不能回寫已入帳來源 |
| 法定書面通知／送達證據 | 畫面可查看及匯出，但未實作完整送達、工資清冊書面通知流程 |

公司優惠額度可用獨立精確調整記錄；不以優惠取代法定來源。事假、病假等不會自動套用特休年資。全薪／半薪／無薪仍是給薪標記，不算薪資或扣薪。

## 2. 法規依據與產品規則

已於 2026-10-17 查核：

- [勞動基準法第 38 條](https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=N0030001&flno=38)：年資取得級距、特休排定、年度終結／契約終止未休工資、協商遞延及通知紀錄責任。
- [勞基法施行細則第 24 條](https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=N0030002&flno=24)：符合資格時取得權利、週年／曆年等協商行使期間、符合資格後 30 日內告知。
- [勞基法施行細則第 24-1 條](https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=N0030002&flno=24-1)：年度終結、未休工資基準與期限、遞延保留原年度基準及優先扣除。

| 已符合年資 | 該次完整基準日數 |
| --- | ---: |
| 滿 6 個月 | 3 |
| 滿 1 年 | 7 |
| 滿 2 年 | 10 |
| 滿 3、4 年 | 每年 14 |
| 滿 5～9 年 | 每年 15 |
| 滿 10 年起 | 16 日起，每滿一年加 1 日，最高 30 |

半年與滿一年是獨立權利，不能只補 4 日。完整來源先建立，年度配置不取代完整已取得權利；離職核對不能只看當年配置。

曆月比例、實際日數折算及一位進位是可設定的產品計算規則，不是宣稱法令只允許此公式。月底／閏日採原始日期錨點與目標月月底規則，需核對後確認。留停、復職、重聘、公司優於法令安排與部分工時均須確認適用條件。相同工作日數、只縮短每日工時的部分工時，不再另減特休日數；比例型須填明確依據，避免比例與減少工時雙重折減。

## 3. 權限、入口與確認流程

入口為管理者「請假管理 → 假別額度 → 特休 → 年資特休制度」，分六頁：權利總覽、制度版本、年資核對、給假試算、年度結算、精確調整。系統管理者可由假別額度入口使用；只有新增特休權限者直接看到年資工作區。

| 操作 | 權限 |
| --- | --- |
| 管理端查看、匯出、給假／結算試算 | `admin.leave.balances.view` 或任一特休操作／額度調整權限 |
| 制度及年資版本 | `admin.leave.entitlements.policy.manage` |
| 給假入帳 | `admin.leave.entitlements.grant` |
| 年度／離職結算 | `admin.leave.entitlements.close` |
| 精確差額預覽及確認 | `admin.leave.balances.manage` |
| 個人明細 | 員工本人；v1.33.0 起主管可用本人原卡號或個人網頁密碼登入，仍需當下有效的明確代辦授權 |

新增三項制度／給假／結轉權限不自動加到既有完整管理者；由系統管理者等具帳號權限管理能力者明確委派。系統管理者可作首次設定。給假與結轉不能代替調整，身份模擬禁止寫入。權限在 API 再檢查，不依賴畫面隱藏。

給假與結算採「條件 → 預覽 → 逐列確認 → 授權人確認」。未來基準日可試算不能入帳。預覽綁定操作者與登入指紋，30 分鐘後或伺服器重啟須重做；條件與資料異動會拒絕舊 revision/digest。確認同一請求重試返回既有 batchId，不重複給假。

## 4. 年資版本與接管

名冊 `hire_date` 是實際到職資料，不直接代表已核對的認列年資。逐人保存認列起日、不計年資區間、工作型態、正常工時、比例依據、特殊日期核對、接管基準及版本生效日。最後在職日取名冊 `termination_date`，計算介面以 `leaveDate`／`leave_date` 表示；日期包含最後在職當天。

不計年資採起日含、復職日不含，不能倒置或重疊。資格事件按實際排除日數移動，不用固定 365 天換算年資。缺必要資料、特殊日期未核對或日期衝突，先阻擋該人入帳。

首次接管記錄起日、核實未休小時、使用迄日及來源；首次年資版本生效日必須等於接管起日，先建立基準再新增後續版本。已有人工額度或正數期初小時須明確確認接管。接管前已取得來源不整批重發，由期初剩餘承接；新資格事件依有效制度發給。首次入帳後接管基準固定，原人工表單／Excel 不可覆寫受管理帳。

後續年資版本須有較晚生效日；正常工時／比例按每個資格取得日適用版本。新版本不得改變既往取得日、法定日數、小時或期限。若提案改到既往來源，保存 `reviewRequired`、原因與 `proposedRevision`，原有效版本不動，後續給假阻擋；明確顯示「已記錄待核對，未套用」。通過核對的有效修訂才解除阻擋。精確額度加減不會自行解除歷史年資待核對。

同一配置年度混用正常工時或進位規則會阻擋給假並要求專用對帳；既有週年／曆年帳也不能靠新版本直接切換制度。

## 5. 完整來源、配置與期間

每個資格事件有完整來源 `annual_leave_grant_lots`。週年制按完整來源期間建立配置；曆年制按協商基礎將完整來源切成年度精確分攤，跨年切片總額保留原來源。

```text
曆年原始分攤 = 完整來源日數 × 本年度交集權重 ÷ 完整來源期間權重
年度原始日數 = 各來源的精確分攤總和
```

曆月權重：完整月為 1，月中區段為實際涵蓋日數／該月日數。實際日數模式則取實際天數比，閏年亦採真實分母；半年批次用本身六個月分母。

折算分段以 `sourceIntersectionStart`／`sourceIntersectionEndExclusive` 保存。曆年可使用窗口另定為 `max(資格取得日, 配置年度1月1日)` 到次年 1 月 1 日，迄日不含。這可避免把半年來源在年中交集結束當成曆年額度提前到期；週年制仍按原完整權利期間結算。

例：2024-07-01 到職，2025-01-01 取得 3 日，2025-07-01 另取得 7 日。曆年整月比例下，2025 配置 `3 + 7×6/12 = 6.5` 日；另 3.5 日配置 2026。2026 滿兩年資格取得後，再加 `10×6/12 = 5` 日，該年合計 8.5 日。尚未取得的 5 日只列預估。已取得且配置後年的 3.5 日不是年終協商遞延，不能再加一次。

同一員工權利帳以資格事件去重，政策換版本不會使同一資格事件再發一次。刪除員工停用舊權利帳並保留歷史；重用工號不承接原帳。

## 6. 精度與分次給假

`raw` 保存精確分子／分母；`ceil_1_decimal` 對同年度加總後的日數無條件進位一位。畫面摘要最多顯示有限小數，不能以摘要回算；例如 `1/3` 小時不改成 0.33。新精確權利帳不受舊人工帳 0.01 小時限制，舊請假時數也不因此重算。

例如 7.01→7.1、精確 7.1→7.1、0.01→0.1。不能逐段進位再加總，也不把這個規則套到已休、預占、負調整或薪資金額。

分次發給以年度原值及既有進位差額重新核對，只記必要差額。重新計算需保留已使用、預占、結算來源；若進位差額變小，只能由未用進位或新來源承擔，不能把已核准的請假變成無來源。原法定來源及計算快照仍保留，年度調整另有流水。

## 7. 結算、遞延與待工資

年度終結逐來源選取，結算年度須與配置年度一致；未到期且未離職不能提前結清。契約終止則核對同一權利帳所有已取得且尚有餘額／預占的來源，包括後年配置；漏選會阻擋整批。取得日晚於結算日的來源不得結算，未到生效日的遞延也不能提前結清。

待審預占、跨邊界舊單缺每日扣抵、未覆蓋時數、負可用或無可結算餘額，均先處理。年資修訂待歷史核對、或名冊到職／離職日與有效年資快照不同，也阻擋結算；先完成年資版本核對。遞延必須保存同意日及證據，日期不得晚於結算基準日；已離職者不能改選年度終結繞過限制，已遞延批次也不能再次遞延。

結算同時扣原來源及建立遞延來源／待工資項目。之後適用的遞延額度優先扣，撤回／作廢請假回原來源；已結算來源的新增剩餘另行核對，不同時增加次年額度。工資狀態僅 `wage_pending`，不產生薪資金額或付款完成註記。

法定工資基準及給付責任仍由薪資作業依 [施行細則第 24-1 條](https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=N0030002&flno=24-1) 核對。畫面有可查閱快照不等於已完成告知及書面通知義務。

## 9. 驗證與正式使用前核對

隔離測試涵蓋年資門檻、月底／閏日、排除年資、部分工時、曆年分母、原值分數、一次進位與分次給假、原請假預占／使用／撤回、到期／離職／遞延、完整來源、防重複、接管、舊 Excel 防覆寫、角色權限、版本與稽核回滾，以及正式 SQLite 備份／重啟精度。測試結果與發布證據以該次更新紀錄為準，不以文件文字代替測試通過證明。

正式使用前仍須確認公司的特休制度與協商依據、員工年資／工時、期初接管與歷史對帳，以及負責通知及薪資處理的人員。完整備份包含新表；不要直接降版後繼續用舊軟體改新權利帳。同步、測試、建置、備份、發布與主機更新沿用 docs 既有規則；GitHub 發布與正式主機部署是分開的作業。
