v1.39 借支清單、午餐與請假操作

工作台總覽新增借支管理的當月待複核筆數、人數、待複核金額與已複核金額，仍顯示八張卡。可在「選擇卡片與排列」從九種選八張。既有排列只將問候語與主題原位置換成借支，其他順序保留；新版個人選擇保存後不再強制替換。未授權及身份模擬不顯示財務資料。詳見指標操作說明。

借支查看登記月份每人一列，以最新一筆申請狀態顯示及篩選，另設更新日期；歷次取消、退回、單號與說明預設收合，點人員或全部展開可看。「有申請紀錄」排除無申請者。查詢、待複核、紙本三頁的四指標在標題下方；紙本補登改為緻密單列，編輯紀錄含版本及單號，金額、備註、儲存、日期分欄，保留同單更正與留痕。

午餐日曆初次載入當月；參加資格列出全員，含未設定者，上方為篩選列。逐人「加入／不加入」開彈窗，修改日期唯讀、生效日預設次月 1 日（可改今日或未來），原因必填。修改時間與生效日分開，未來及歷次設定保留；版本過期不能覆蓋。詳見午餐操作說明。

員工與主管代辦新增請假事由必填。實際請假與午休 12:20–13:00 有正長度重疊時，只有當日已參加、供餐、仍用餐且未截止／結單的對象預勾紅字「當天不用餐」，可取消預勾。這與休息時數計算不同。送件成功就停餐，不等核准；退回或撤回不自動恢復用餐，仍需依午餐截止規則另行恢復。授權、資格、截止及稽核重新檢查，請假與本次停餐一起成功或一起回滾。

主管代辦以建立代辦申請／查看代辦紀錄分開，建立時只有本次代辦員工勾選；查紀錄才出現單選「紀錄查詢對象」。請假預設 08:20–17:00、加班預設 17:30–19:30，原指定對象、核准流程、確認與留痕保留。詳見代辦操作說明。所有網頁往下捲動後，右下角可回到最上方，不會提交或清除表單。

正式升級先備份主機 SQLite 與 WebCredentials，安裝重啟後核對健康版本 1.39.0。本機測試服務保留供查看，與正式主機分開；安裝檔或 Git 推送不代表正式更新，既有 ERP 契約維持。詳見部署驗收。

v1.38 借支分頁、紙本補登與管理者查詢

管理者「借支管理」與「午餐團膳」採與請假、加班一致的左右模板，標題及操作說明位於工作台總覽下方的內容區。借支左側分為查看登記月份、管理部待複核、紙本核准補登、活動設定；午餐分為午餐日曆、參加資格、供餐制度。

借支「查看登記月份」是唯讀全員名冊，可按月份、人員、部門及狀態篩選。沒有申請也列出：無申請灰色，待複核與金額黃色，已取消／已退回與金額紅色，已複核／補登記與金額綠色。待複核工作頁保留月份明細與總額；審核及取消在當前畫面開彈窗，核准與退回說明選填，取消原因仍必填。

具獨立紙本借支補登與修正權限的人員可在全員表逐列填金額及選填備註，確認後直接列為補登記；儲存後可更正同筆內容，保留原單號、原規則、扣回月份及每次前後操作紀錄。員工在自己的「查看登記月份」看到最新結果。可補歷史月份，不受員工開放登記日限制，但新增仍檢查已設定的金額及有效筆數上限；更正沿用該筆原金額上限，不增加筆數。已離職員工限離職當月或之前。詳見借支操作說明。

紙本新增、更正與取消都提供 ERP 修訂事件；ERP 以同一單號的較新版本更新來源，不把每次更正當另一筆發款。已發放或已扣薪的差異需人工核對。既有帳號不因升級自動取得新紙本權限，須明確授權；主管代辦權限不包含借支。詳見ERP 交接文件。

「請假出勤查核」初次進入只顯示臺北時間當月，提供查核月份、部門、員工、警示類型與「查詢」、「回到本月」。打卡警示依打卡月份、無打卡警示依請假日期歸屬；CSV 使用最近一次成功查詢的條件。黃色容許時間、紅色衝突及既有判定維持，不改寫請假或打卡。

部署前備份正式主機 SQLite 與 WebCredentials，安裝重啟後核對健康檢查版本 1.38.0 並重載網頁；安裝檔或 GitHub 推送完成不代表正式服務或 ERP 接收端已更新。詳見部署與驗收。

v1.37 申請預設時間、獨立休息與出勤查核

員工「我的請假」及管理者「紙本核准請假補登」的新申請預設為 08:20–17:00；員工「我的加班」與「紙本核准加班補登」預設為 17:30–19:30。既有單修正帶回原起訖，不用新預設覆蓋原資料；員工工作台首頁與原審核、權限、ERP 流程維持原樣。

請假每段可另填休息時間（分鐘）。完整涵蓋 12:20–13:00 時預帶 40 分鐘，其他時段預帶 0 分鐘；只涵蓋部分午休時請自行填實際休息。08:20–17:00 扣 40 分鐘後為 8 小時。修改休息會重算淨時數，手動休息或淨時數在改起訖後保留；員工可按「恢復自動休息與時數」，紙本補登可按「恢復自動計算」重新帶入。送出前核對各段及合計。

管理者「請假管理 → 請假出勤查核」新增黃色容許時間範圍：打卡在真正請假開始／結束前後 20 分鐘內（含邊界）時提示；更深的請假區間內打卡仍為紅色。分段間空檔不列為請假，相接時段及舊跨日單的午夜切點不新增容許邊界。全天有區間外打卡、部分請假無打卡等提醒保留，CSV 同步顯示狀態；不修改原假單、核准或打卡。

新填休息與淨時數共同保存，扣假、報表及 ERP 使用淨時數，不再扣一次休息。未保存休息的舊單顯示「舊單未記錄」，不推測補填或自動重算。完整操作見 日曆操作說明與 多時段請假說明。

升級新增可為空值的段落休息分鐘欄位；先備份真正服務主機 SQLite 與 WebCredentials，安裝重啟後核對健康檢查版本 1.37.0 並重載網頁。完整備份保留休息資料；需要回復時停服務並還原升級前完整備份，不讓舊程式繼續修改新版資料。安裝檔或 GitHub 推送完成不代表 TC-150 已更新。

v1.36 我的請假與我的加班

員工「請假申請／我的請假紀錄」整合為「我的請假」，「加班申請／我的加班紀錄」整合為「我的加班」。只有這兩個內頁與對應入口調整；員工首頁身分、出勤、打卡、常用功能與其他模組保持原外觀。四個舊入口依原排序中先出現的位置合併為兩個，其他功能的相對順序保留，仍可自行調整。

同頁提供日曆／月內清單、當日紀錄、整張單詳情與新增申請。瀏覽模式點日期只查紀錄，按「新增申請」才開始選日與填寫。桌面日曆與工作面板並排；手機使用精簡日曆及全高編輯面板，底部核對摘要與送件。

  1. 請假：選一種假別、實際日期與共用時段，再逐段調整；可包含不連續日期及同日不重疊的數段，核對日數、段數與實際時數後合為一張單送審。
  2. 加班：保留單一連續起訖。跨午夜可使用隔日快捷操作，仍須核對完整結束日期；分開日期的獨立加班各自申請。
  3. 時數：起訖差值不等於一定全數計入，須扣除休息。v1.37 請假提供獨立休息分鐘及自動帶入，見上一節；實際時數不得超過扣除休息後的時間，人工調整後仍須核對。
  4. 查詢與撤回：點事件查看整張單，撤回也影響整張單。請假仍經指定主管及管理部終審，待主管／管理部時可依原流程撤回；加班仍由指定主管審核，僅待主管時可撤回。

請假與加班各保留一份本次登入期間的記憶體草稿，切月份、查紀錄、切其他功能或資料更新後可接續；送出失敗保留輸入。重新整理、關閉頁面或登出後不保存，換身份時也清除。個人排序會跨裝置保存，申請草稿不會。

歷史月份限制、本人／本人代申請資料範圍、指定主管、任一／必審規則、授權對象、原單號、歷史日期模式、扣假、稽核與 ERP 輸出維持相容。主管代辦與管理者入口仍按原流程，員工不增加修改已核准單的權限。詳見 請假與加班日曆操作說明。

正式主機更新前備份 SQLite 與 WebCredentials；安裝重啟後核對健康檢查版本 1.36.0，再重新載入網頁。安裝檔或 GitHub 推送完成不代表 TC-150 已更新。

v1.35 員工首頁、個人入口順序與管理權限

員工首頁將工號、姓名、部門、職稱、性別與國籍整合成身分摘要，並緊湊呈現今日紀錄、有效打卡、近 7 日紀錄、目前班別與下一次動作；欄位與統計口徑不變。時間、日期、最近打卡與打卡操作集中顯示，功能入口依畫面寬度自動換列，手機也不必沿長橫向捲軸找功能。

員工可按「調整我的順序」，用「上移／下移」安排常用功能，再按「儲存排序」保存到本人帳號。跨裝置登入同一帳號也能取得；「恢復預設」先改草稿，仍須儲存才生效。身份模擬不能保存。個人順序不改其他員工或管理者／開發人員的全域導覽，不增加資料或操作權限。

舊「完整管理者」改名「一般管理者（既有模板）」並保留原權限；新增的「完整管理者」才包含網頁帳號、特休制度與借支等目前全部管理者功能。升級不自動增加既有帳號權限；需由有權限的人員選取新版模板並儲存帳號權限。模板不授予開發人員角色，也不代替個人密碼及管理登入啟用。

借支單筆上限已確認為新臺幣 15,000 元（1.5 萬元），由管理者自行調整活動設定；實際生效值以正式主機儲存結果為準。本次更新不修改正式活動規則。詳見 員工工作台與管理權限操作說明。

v1.34 多時段請假、借支與裝置備援

請假可在同一張單加入不同日期與時段，也可同日加入上午、下午；先建立清單再送出，逐段填淨時數。主管與管理部審核仍以同一張單處理，空檔不算請假。舊單保留原語意。詳見 請假操作說明。

員工「我的借支」自行登記，由管理部直接審核，不經主管、不開放主管代辦。管理者「借支管理」可依獨立權限調活動日期、單筆上限、有效筆數與預計扣回月份，並審核、取消及下載總表。日期預設每月15～20日；單筆上限已確認預計為15,000元，由管理者自行設定，金額與筆數未完成設定前停用。既有申請保留送件規則，核准不表示已發放或扣薪。詳見 借支操作說明。

ERP須另授予salary_advances權限並完成接收端；修訂事件含取消紀錄及游標驗證，避免重複或遺漏。將 交接文件及提示詞交給ERP代理依現行正式程式修改。

裝置ID與分員工憑證增加網站儲存及Cookie備援，有效憑證可找回原綁定，兩種儲存都不可用時阻止新增；診斷可看來源與恢復結果。全部資料被清除仍無法證明原電腦，須核對瀏覽器政策及舊綁定。更新前備份真正主機SQLite與WebCredentials；安裝重啟核對本次發布版本，不可直接降版寫入新版資料。

v1.32 裝置綁定與登入診斷

保留裝置綁定，新增每人 1～4 台上限；舊設定沒有上限時採 4 台。不同瀏覽器、設定檔或網站來源可能視為不同裝置，不是電腦硬體序號。

安全設定的裝置清單可篩選三台以上人員；登入診斷預設失敗，也可查全部或成功，核對最近 14 日最新 200 筆的錯誤碼、裝置 ID、來源網址、IP 與憑證有無。缺少或錯誤憑證仍阻擋，不自行解除綁定。

裝置沒有每日到期，登入工作階段則為 12 小時。升級前未保存的失敗不能補回，請於安裝重啟新版後再請受影響員工登入，依新紀錄排查。完整流程見 裝置綁定與登入診斷操作說明。

v1.31 跨日請假逐日選擇

本人申請、管理者補登／修正及授權主管單筆／批量代辦請假，都可在一張單中勾選實際需請假的日期。跨日預選週一至五，週末輪班可勾回、國定假日手動取消。這不是正式排班或假日判斷；請核對公司實際安排。

逐日填扣除午休等休息後的實際時數，或填相同時數後套用；總數自動加總。空選、未填、重複或超過當日範圍的時數會阻擋送出。審核與歷史可展開請假日期、每日時數與排除日。

未勾選日不扣額度、不列請假日曆／考勤／午餐提醒，也不阻擋另外申請。舊單不自動重算；舊紙本修正時重新確認選日，保存後才採逐日模式。一般線上核准單沿用原處理權限，不新增任意改單權。

完整流程、欄位與例子見 跨日請假逐日選擇操作說明。更新前備份真正主機 SQLite 與 WebCredentials，安裝重啟後核對版本 1.31.0；舊版不識別排除日，不可直接降版操作新版資料。

變更位置後先儲存，第二位置留白可停用。路徑及選擇資料夾視窗均屬於服務主機；主機 Windows 帳號必須能存取 NAS。儲存設定不測試 NAS 連線，真正備份時才寫入；失敗不自動改存其他位置。排程與緊急備份沿用原第一位置或任務設定。

v1.29 年資給假與年度結轉

文件更新：本次更新借支四個子頁、全員月份查詢、紙本核准補登及更正、獨立權限與 ERP 修訂交接，並補充午餐三個子頁及請假出勤按月篩選。既有員工工作台、申請休息時間、日曆、個人帳號、裝置診斷、年資給假與備份還原說明仍適用。 部署還原與版本紀錄請同時參照 docs/快速部署還原說明.md 與 docs/更新紀錄.md。

2. 最高權限原則

本系統的最高權限不是單一帳號包辦全部工作，而是分成兩個核心權責：

系統管理者

獨立於員工資料之外，主要管理「誰可以用哪些角色登入」以及「管理者可操作哪些功能」。這是帳號與權限的最高入口。

開發人員

綁定員工帳號，負責系統密碼、自動化任務、操作稽核、完整資料庫備份還原、主功能頁籤排序、系統狀態與 API 目錄檢查。

第一次使用時請先登入系統管理者，建立可信任的開發人員與完整管理者帳號，再由開發人員設定備份、自動化與系統密碼。不要把日常員工帳號直接當成最高權限共用帳號。

3. 角色與預設帳密

角色 登入方式 預設資訊 第一次使用後必做
系統管理者 登入入口選「系統管理者」，使用獨立帳號與密碼。 system-admin / TC-SYS-0000 立即修改系統管理者帳號或密碼，並記錄在公司內部安全保存位置。
開發人員 一般登入輸入工號 + 個人網頁密碼，登入後選擇已授權的開發人員工作台。 個人網頁密碼沒有共用預設值；桌面開發人員密碼預設 0000，不再用於網頁一般登入。 先授權角色並設定臨時網頁密碼，首次登入須修改，再設定備份與桌面開發人員密碼。
管理者 一般登入輸入工號 + 個人網頁密碼，登入後選擇已授權的管理者工作台。 個人網頁密碼沒有共用預設值；桌面管理者密碼預設 TC5128，不再用於網頁一般登入。 授權角色及功能，設定臨時網頁密碼；首次修改後，再確認管理者功能範圍。
員工 使用員工編號 + 卡號登入。 卡號來自員工資料欄位。 確認員工工號、姓名、部門、職稱、卡號、密碼與個人資料正確。
預設密碼只適合第一次開通。正式使用前須更換獨立系統管理者密碼、桌面開發人員密碼與桌面管理者密碼；網頁管理者及開發人員另外使用各自的個人網頁密碼。

4. 第一次開通順序

  1. 啟動桌面系統或開發環境，確認 Express 服務正常運行在 3000 連接埠。
  2. 開啟網頁版入口：http://127.0.0.1:3000/browser/。
  3. 使用系統管理者預設帳號登入，先修改系統管理者帳號或密碼。
  4. 確認員工資料是否已存在。若沒有員工資料，先建立或匯入最基本的員工名冊。
  5. 在帳號權限管理中，指定至少一位完整管理者與一位開發人員。
  6. 已授權的人員可先用本人卡號登入，於「個人帳號」自行首次建立密碼；亦可由「個人網頁密碼管理」設定臨時密碼，再由本人登入修改。不會改動員工卡號或桌面密碼。
  7. 系統管理者在「個人網頁密碼管理」→「管理工作台登入啟用」選已指定管理角色的人員，驗證自己的登入密碼並填原因，按「啟用管理登入」。新建密碼不會自動開通管理工作台。
  8. 管理者／開發人員由一般登入輸入工號與個人網頁密碼，完成臨時密碼修改後重新登入，再選擇工作台。開發人員設定備份，管理者建立班別、請假與報表設定。
  9. 仍可在網頁管理者安全設定修改桌面管理者密碼，或在開發人員系統設定修改桌面開發人員密碼；這些操作仍使用目前桌面開發人員密碼驗證。
  10. 建立一筆測試員工登入與打卡紀錄，確認裝置綁定與 GPS 權限是否符合公司政策。
  11. 建立一次完整資料庫備份，確認備份檔與 manifest 可成功產生。
  12. 匯出一份考勤報表，確認欄位順序、請假紀錄與 ERP 預期格式相容。

5. 帳號權限管理

帳號權限可以由「系統管理者」或「開發人員」管理。系統管理者是最適合第一次開通時使用的入口，因為它不依賴任何員工帳號。

可授權角色

  • 員工：所有員工帳號預設都保留員工登入權限。
  • 管理者：已授權角色、設定個人網頁密碼且另行啟用管理登入後，可進入管理者工作台；功能仍受權限模板或自訂權限限制。
  • 開發人員：已授權角色、設定個人網頁密碼且另行啟用管理登入後，可進入開發人員工作台。

個人網頁密碼與工作台切換

  • 一般員工可繼續使用既有工號與卡號，不需要全員重建帳密。卡號登入只能使用員工工作台。
  • 個人網頁密碼與卡號、員工基本資料的密碼欄位、桌面共用密碼分開。個人密碼為 8 至 128 字元，前後不可留空白，也不可與卡號相同。
  • 個人網頁密碼登入後依目前角色及管理登入啟用狀態選工作台；只有員工工作台時直接進入。上方可切換可用工作台，後端每次重新核對權限；進入員工工作台仍須通過裝置綁定，GPS 規則不變。
  • 員工本人登入後皆可開啟上方「個人帳號」。尚未設定密碼者輸入目前卡號、新個人網頁密碼與確認新密碼，按「建立個人網頁密碼」自行首次設定，不需要開發人員先設定。
  • 已有密碼者仍須用目前個人網頁密碼、新密碼與確認新密碼修改。即使用卡號登入，也不能憑卡號覆寫既有個人密碼；忘記密碼請走具權限人員重設流程。身份模擬不可設定／修改密碼。
  • 管理端建立臨時密碼／重設後，下次個人密碼登入必須先修改；本人自助首次設定不會再要求修改一次。設定／修改／重設使該人員原有網頁登入與即時同步連線失效，請重新登入，登入最長有效 12 小時。
  • 系統管理者保持獨立入口，不使用員工個人密碼；在「登入帳號」表單修改自己的獨立帳號與密碼，修改後全部系統管理者連線須重新登入。

管理端設定、重設與查看目前密碼

  • 系統管理者工作台及「開發人員工作台 → 系統設定 → 帳號權限管理」提供「個人網頁密碼管理」，可設定／重設與查回員工目前有效的個人網頁密碼，不提供歷史密碼。開發人員的密碼管理及管理登入啟用放在右側帳號權限管理內容區，不在統計數字上方。
  • 查看或重設前，必須輸入操作者自己的目前登入密碼；系統管理者使用獨立密碼，開發人員或管理者使用個人網頁密碼。每次操作均留稽核，但不寫入明文密碼。
  • 使用「一般管理者（既有模板）」者，須改選新版「完整管理者」，或在自訂權限另勾「重設一般員工網頁密碼」及需要的「查看一般員工目前網頁密碼」，儲存後才能使用相應功能。v1.35 的完整管理者模板包含這兩項權限，升級不會自動替舊模板增加權限。受委派管理者只能操作員工角色帳號，不能重設或查看管理者、開發人員或獨立系統管理者。
  • 查回密碼顯示後可按「隱藏」，亦會於 60 秒後、切換目標、切換工作台、登出或頁面隱藏時清除，不存入瀏覽器儲存空間。

管理工作台登入獨立啟用

  • v1.33.0 升級時既有個人密碼保留管理登入啟用能力，仍受既有角色與功能權限限制；不會自動新增角色。新版首次自助或管理端新建密碼預設管理登入未啟用；既有密碼修改／重設保留原狀態。
  • 只有真正登入的獨立系統管理者或開發人員，可在「個人網頁密碼管理」的「管理工作台登入啟用」區，選「管理工作台帳號」、輸入「驗證你的登入密碼」與「啟用／停用原因」，再按「啟用管理登入」或「停用管理登入」。只列已指定管理者／開發人員角色的人員，尚未設定密碼者先完成密碼設定。
  • 一般管理者即使有員工密碼重設權限，也不能啟用管理登入。身份模擬不可操作。啟用／停用保存稽核並撤銷受影響工作階段，本人須重新登入；卡號始終只進員工工作台。

首次設定、忘記密碼、管理入口與常見問題，詳見 個人帳號與管理工作台登入說明。

依需求提供查回密碼，代表具授權者及取得完整資料庫與金鑰備份的人可以解密目前密碼。 請限縮授權、保護主機與備份；正式對外連線應使用 HTTPS 或受控 VPN，純 HTTP 無法保護密碼與登入 Token 的傳輸。

6. 管理者基礎設定

完整管理者登入後，建議依序設定下列內容。管理者工作台的主功能依權限顯示，包含人員資料、安全設定、借支管理、班別設定、手動補登、考勤報表、請假管理、加班管理、午餐團膳、主管指定、系統設定、響鈴設定與主題特效。網頁帳號功能在安全設定，特休制度在請假管理內，仍依個別功能權限開放。

人員資料

  • 基本欄位包含工號、姓名、性別、部門、職稱、卡號、密碼、國籍、身分證字號、生日、到職日、離職日與備註。
  • 部門需先在人員資料內的「部門設定」建立並啟用，新增或編輯員工時只能從既有部門清單選擇，不再任意輸入部門文字。
  • 舊有員工與主管審核路徑中已存在的部門會自動匯入部門設定，仍被員工或主管路徑使用中的部門不可直接刪除或停用。
  • 延伸欄位包含銀行帳號、手機、緊急聯絡人、聯絡電話、戶籍地址、通訊地址與家庭狀態。
  • 匯入前先整理 CSV 欄位，避免卡號重複或工號空白。

安全設定

「員工網頁打卡權限」可逐員工勾選允許線上打卡，取消勾選後填原因、確認並儲存。需安全設定管理權限，系統管理者也有同名區域。預設維持允許；停用不影響登入、請假、加班、團膳或實體卡。後端每次打卡重新檢查，舊登入也立即受限制。

員工選取沿用紙本補登的搜尋、部門篩選及卡片多選。「選取顯示」只追加篩選中的員工，「清除」取消全名冊勾選；篩選隱藏不會停用已勾員工，須確認儲存才套用。

  • 裝置綁定預設啟用，每人上限可選 1～4 台，舊設定缺少上限時採 4 台；帳號驗證成功後，新 ID 在上限內可綁定，原 ID 仍須有效憑證。
  • 遠端打卡可要求 GPS，預設最大 GPS 誤差為 300 公尺。
  • 裝置清單可篩選 3 台以上待查看人員，管理者核對來源與使用情況後，再依需要解除特定舊綁定；調低上限不刪原裝置。
  • 裝置登入診斷提供最近 14 日最新 200 筆成功或失敗，預設失敗，可搜尋人員與裝置、對照錯誤碼／網址來源／IP／憑證有無。資料不含密碼與憑證原文；不能補回新版以前未記錄的失敗。

班別與補登

  • 先建立公司實際使用的班別名稱、上班時間與下班時間。
  • 手動補登屬於高風險操作，應只開給考勤或完整管理者，並保留稽核紀錄。

系統顯示、響鈴與主題

  • 系統設定可調整主標題、副標與登入頁說明文字。
  • 響鈴設定可管理排程、自訂聲音與響鈴歷史。
  • 主題特效可管理節日特效、主題排程與自訂主題圖片。

7. 考勤與請假設定

打卡來源

系統會保存桌面端、密碼、手動補登、API、瀏覽器與請假等來源。這些來源會影響稽核與報表判讀。

請假流程

  • 網頁「我的請假」整合申請與紀錄，日曆／清單、選日、時段編輯與整張單詳情留在同頁；桌面並排、手機使用全高編輯面板。管理者「請假紀錄」與「進階查詢／匯出」保留原入口及紙本補登流程。
  • v1.23.0：管理者「安全設定」→「員工紀錄可見範圍」，或系統管理者工作台的同名區塊，可設定全體員工的請假、加班回看月數。須有安全設定管理權限，填原因並確認後儲存。N 表示本月加前 N 個月，0 表示僅本月；取消限制可回復完整歷史，升級預設不限制。
  • 員工「我的請假／我的加班」顯示最早可查月份，較早資料請洽有請假終審／加班查看權限的管理者。這是查詢限制，不刪除紀錄；指定主管原待審與授權員工的代辦歷史仍依原授權查看，不能透過這些入口查未授權員工。
  • 日曆採台北時間，完整查詢跨月紀錄；跨日仍是同一筆 ID，明細時數為整筆儲存時數，不重算、不改寫申請或報表。詳見 docs/請假與加班日曆操作說明.md。
  • 請假類型支援小時或天數單位，可設定是否需附件、是否扣假、是否給薪與啟用狀態。
  • 管理者「主管指定」提供「主管審核／代辦主管」側邊導覽。審核主管改為每位員工指定一位，請假／加班共用，可批量指定及跨部門，不按部門自動繼承。升級轉換當時有效路徑但不改派已送出案件；詳見 docs/主管審核個別指定說明.md。
  • 主管以員工身份登入審核，請假仍須管理部終審。多位代辦授權保持獨立；代辦模式、原因、確認與儲存按鈕在寬螢幕同列，手機換行。未指定審核主管的新員工需先由管理者設定。
  • 請假可支援半小時、半天、一天與跨時段情境，系統會保存開始、結束與時數。
  • 試行期若員工已完成紙本核准，管理者可在請假管理中使用「紙本請假補登」，直接建立已核准請假紀錄，並寫入操作稽核。
  • 紙本請假補登可依部門篩選並一次多選員工，適合同一日期與時間區間內多位員工共同請假的情境，避免管理者重複輸入相同資料。
  • v1.37 員工與紙本請假新申請預設 08:20–17:00，可另填休息分鐘；完整涵蓋 12:20–13:00 時預帶 40 分鐘、淨時數 8 小時，其他時段預帶 0 分鐘。手動休息在改時間後保留，改休息會重算；舊單未記錄休息時保留原淨時數。
  • 若紙本請假補登輸入錯誤，請到「請假紀錄」找到該筆紙本補登，按「修正」即可帶回原資料調整；儲存後會直接更新同一筆已核准紀錄，補登編號不變，並保留修改前後完整稽核。若整筆不需要，按「作廢」即可。
  • 「修正」與「作廢」只會出現在仍為已核准的管理者紙本補登，一般員工線上申請不會出現這些按鈕；操作需要紙本請假補登權限並會留下稽核紀錄。
  • 請假與加班紀錄的「操作」欄會固定在表格右側；即使欄位較多，也不必先將表格水平捲動到最右邊，就能看到可用的「修正」與「作廢」按鈕。
  • 紙本請假補登不會取代線上申請流程；員工自行線上申請仍會依主管與管理部審核路徑處理。
  • 請假出勤查核在真正請假邊界前後 20 分鐘內顯示黃色「容許時間範圍」，深處打卡仍為紅色；相接時段與歷史午夜不新增容許邊界，全天區間外打卡與無打卡等原提醒保留。警示及 CSV 僅供核對，不改寫考勤。

加班流程

  • 網頁「我的加班」同頁提供日曆／清單、連續起訖申請及整張單詳情；保留本人與本人代申請的既有紀錄，查詢時核對對象。管理者「加班申請紀錄」與指定主管的獨立「主管審核」維持原入口與範圍。
  • 「我的加班」新申請僅本人送件，主管本人也須由指定主管審核；替其他員工申請一律使用「主管代辦」，要有明確代辦授權、本人卡號或個人網頁密碼登入、代辦原因及表單要求的核准確認。本人申請與稽核寫入同一交易，失敗整筆回滾。跨夜必須核對完整結束日期，分開日期的獨立加班不能合成一張單。
  • 試行期若加班已完成紙本核准，管理者可在加班管理中使用「紙本加班補登」，直接建立已核准加班紀錄。
  • v1.37 員工加班與紙本加班補登的新申請預設為 17:30–19:30（2 小時）；仍須按實際核准內容確認起訖、跨日與扣除休息後的加班時數，修正原單不覆蓋原時間。
  • 紙本加班補登可依部門篩選並一次多選員工，適合同一日期與時間區間內多位員工共同加班的情境，系統會分別建立每位員工的加班紀錄。
  • 若紙本加班補登輸入錯誤，請到「加班申請紀錄」找到該筆紙本補登，按「修正」調整；系統會直接更新同一筆已核准紀錄，補登編號不變，並保留修改前後完整稽核。只需取消錯誤資料時可直接按「作廢」。
  • 已作廢的紙本補登仍可在紀錄中查核，但不會列入已核准請假、已核准加班或薪資請假／加班明細。
  • 加班核准紀錄只供查核、警示與匯出報表使用，不會直接修改打卡或出勤時間。

個人假別額度（v1.26.0）

管理者工作台 → 請假管理 → 假別額度，可個別或批量設定每位員工的特休及其他假別天數，並匯出 Excel 填寫後預覽匯入。系統管理者也有獨立額度區塊。預設曆年制、每日 8 小時；新設定工時可調整，原年度工時不重算。

  • 首次設定選全年總額（含原年度核准及待審）或期中剩餘額度（指定扣抵起日）；先確認基準再儲存，避免舊單重複扣抵。
  • 待審只預占，管理部核准才列使用，撤回／駁回／作廢釋放。紙本修正維持原單 ID，依差額更新餘額。
  • 員工「我的請假」看本人當年餘額；主管代辦只看明確授權員工。未設定不等於沒有請假權利，負餘額提示但不自動拒絕申請。
  • 跨日額度請假填每日實際時數，排除非工作日及午休；跨年分別扣各年度。跨邊界舊單缺分配時先標示待確認，管理者補分配，不改原單資料。

完整初次設定、Excel、權限與備份流程見 員工假別額度管理說明。第一版不自動按年資核給、不自動結轉或計算未休工資。

考勤報表與 ERP

考勤匯出模板包含薪資系統、異常稽核、報表分析、薪資含請假明細、完整格式與自訂格式。若要讓薪資與請假資料搭配得好，建議使用「薪資含請假明細」或自訂格式，並保留以下欄位：

  • 工號、姓名、部門、職稱、日期、時間、班別、打卡類型、考勤狀態、來源。
  • 紀錄種類、假別、請假開始、請假結束、請假時數、請假單號。
系統已設計讓核准請假也能成為考勤報表中的可查核紀錄，避免當天沒有打卡就完全沒有紀錄，方便後續 ERP 或薪資系統提取。

午餐團膳

  1. 管理者工作台 → 午餐團膳 → 供餐制度，設定生效日期、供餐星期、預設截止時間及全日請假提醒工作區間。初始不假設週一至週五供餐。
  2. 參加資格由管理者登記；加入後供餐日預設用餐。日曆選日期，可另外設定假日供餐、臨時停供與本日最晚變更時間。
  3. 員工工作台 → 我的午餐團膳，選日期登記不用餐或恢復用餐。已核准全日請假仍預訂時有提醒及直接取消按鈕，不自動取消。
  4. 台北時間到達截止或提前結單後，員工不可自行修改。管理者於日名單「代登／修正」填原因，直接更新同一筆登記並保留前後稽核。
  5. 先實際通知供應商，再按「結單並記錄交單」；目前餐數與已交單份數分開。後續異動顯示差額與人員，再次通知供應商後才「更新供應商交單」。

第一版僅管理午餐預訂，不是實際領餐，不計費、不連動薪資，也不自動送單。詳見 午餐團膳操作說明，包含權限、生效日期、退出、月報、備份與部署。

主管代辦

v1.22.0：指定代辦主管可多選 1 至 100 位員工及多位主管，一次套用。預設新增保留原主管；取代才以本次勾選替換原名單，空白取代需額外確認清除全部授權。填原因、勾確認並按「批量儲存主管指定」後才生效，未選員工不變。每人保留前後稽核與共同批次編號，資料過期或任一稽核失敗整批不寫入。

v1.21.2：主管指定與代辦表單使用可用全寬。員工名單可拖曳右下角或使用「名單高度」滑桿，在 100 至 1200px 間調整；三個設定名單高度分別保留於本次頁面開啟期間，重新載入恢復預設。調整高度不改勾選、授權或資料，也不觸發未儲存提醒。

v1.21.1：設定主管的員工、查看紀錄員工採用可搜尋／部門篩選的卡片單選；指定主管及代辦表單採用相同樣式多選，與紙本補登一致。請假／加班選日期後直接顯示申請欄位，不需先按「代申請」；篩選保留勾選，切換或重設未儲存內容時會先確認。

v1.21.0：主管代辦表單可多選 1 至 100 位員工，批量送相同請假、加班或午餐內容；任一人衝突、授權撤銷、資料過期或稽核失敗，整批不寫入。日曆員工只決定查看紀錄，表單勾選才決定代辦名單，每人時數並非總時數。

管理者「主管指定」以側邊「主管審核／代辦主管」分開設定。審核路徑沿用 admin.leave.settings，可逐員工指定多位主管，選任一核准或指定必審者；代辦授權仍獨立。代辦子頁的「審核主管代辦授權待確認」只列待盤點關係，不自動擴大請假／午餐及歷史查詢權。請假假別仍在請假管理。

  1. 系統管理者工作台的「指定代辦主管」，或管理者工作台「主管指定」，多選員工及主管、選新增或取代模式、填原因並確認批量儲存。可跨部門，員工與主管名單不可重疊（不能指定本人）；自訂管理者需有 admin.supervisors.manage 權限。
  2. 首次建立代辦授權表時為空，不按部門自動授權；既有授權升級保留。主管以本人原卡號或個人網頁密碼進員工工作台「主管代辦」，只看到明確指定的員工。主管及被代辦員工均不須為代辦設定／重設密碼。
  3. 日曆選日期代申請請假，依原任一／必審等規則完成主管階段後，仍送管理部終審；未終審可依規則填原因代撤回。已核准請假不提供任意改寫入口。
  4. 加班保留員工本人申請；主管替員工送件統一在主管代辦頁，按原任一／必審等審核規則處理，卡號登入不跳過審核。只有審核資格不能代送，須盤點確實需要的代辦授權；原代送歷史、時數、ID 及原案件審核人不改寫。
  5. 午餐代登必填原因，遵守每日截止及結單；截止後由團膳管理者處理，不授予主管供餐制度或交單權限。

每次送出重新檢查授權、保留實際操作者與前後稽核。撤銷立即生效；刪除員工清除授權，不刪歷史申請。詳見 主管代辦操作說明及 批量代辦與網頁打卡權限說明。v1.36 只重構員工本人的請假／加班整合內頁，不改本節主管代辦流程或權限。

8. 開發者維運工作台

開發者工作台是系統維運的核心。第一次使用時，請不要只做帳號授權，也要完成以下維運設定。

系統設定

  • 變更桌面開發人員密碼（原系統密碼）；桌面登入、桌面管理者密碼變更與測試身份切換仍使用它。網頁一般登入已改用各自的個人網頁密碼。
  • 視需要啟用開發人員身份切換，用來測試管理者或員工流程。一般員工與管理者登入頁不接受系統密碼作為萬用密碼。
  • 設定主功能頁籤排序。開發人員可以在開發者工作台調整管理者與開發者工作台的主功能頁籤全域排序，並可還原預設。
  • 管理帳號權限。開發人員可和系統管理者一樣調整員工可登入角色與管理者功能權限。

稽核與系統狀態

  • 操作稽核紀錄可查登入、權限、打卡失敗、備份還原、密碼變更等重要事件。
  • 稽核封存可設定保留天數，預設保留 180 天。
  • 系統狀態會顯示服務狀態、連接埠、版本、資料庫位置、資料量、備份狀態、API 數量與自動化狀態。

9. 完整資料庫備份與還原

完整資料庫備份會產生 SQLite 資料庫檔與 manifest；已有個人網頁密碼時，另產生同名 .db.web-credentials.json 金鑰附檔，manifest 記錄其檔名及 SHA256。搬移時必須一起保留；缺少所需金鑰會停止還原，不覆蓋現有資料庫。核心資產 ZIP 也包含營運資料中的 WebCredentials 資料夾。

第一次備份設定

  1. 使用開發人員登入。
  2. 進入「匯出設定」的「完整資料庫備份與還原」。
  3. 核對位置 1 的打卡鐘備份資料夾；留空使用主機預設 DatabaseBackups。位置 2 初始為指定 NAS，可改路徑或留空停用。
  4. 設定保留份數（預設 30 份），按「儲存備份設定」。路徑由主機存取，儲存設定不測試 NAS 連線。
  5. 在「本次主機端存放位置」選其中一處，按「立即完整備份並下載」。核對所選位置的檔案與目前操作電腦的瀏覽器下載清單；頁內最近清單只列位置 1。
  6. ZIP 下載中斷時可在 15 分鐘內、同一登入下按「再次下載這份備份」。詳細欄位與疑難排除見 資料庫備份與下載說明。

還原規則

  • 下載 ZIP 先完整解壓，保留資料庫、manifest 與金鑰附檔在同一資料夾，還原時選 .db；不能直接選 ZIP。TC039 測試請確認連到 TC039 本機網址。
  • 還原前系統會先建立還原前緊急備份。
  • 來源檔需通過 SQLite 檢查與必要資料表檢查。
  • 執行還原前必須輸入確認文字：還原資料庫。
  • 還原會覆蓋目前使用中的資料庫，正式環境請先取得主管或系統負責人確認。

專案核心備份

除了網頁內的資料庫備份，專案也提供核心資產備份腳本，可打包原始碼、文件、使用者資料庫與自訂素材。

powershell -NoProfile -ExecutionPolicy Bypass -File ".\scripts\backup-core-assets.ps1"

自動化任務目前可處理匯出、刪除與完整資料庫備份。第一次設定時建議先做「完整資料庫備份」排程，再設定報表匯出。

刪除 依系統允許的清理目標執行。 清理特定歷史資料。正式使用前要先確認保留政策。
完整資料庫備份 任務目標欄位會隱藏，由系統固定使用完整資料庫備份目標。 每日或每週建立完整資料庫備份，是最重要的自動化保護任務。
設計上「完整資料庫備份」不應出現在匯出或刪除的任務目標裡；只有任務類型選完整資料庫備份時，系統才會在後端固定使用備份目標。

11. API 與 ERP 匯出

API

系統提供外部 API，可查詢員工、打卡紀錄、考勤報表、請假申請紀錄、加班申請紀錄，也可建立 API 打卡。這些 API 需要先由開發人員工作台啟用，並使用多組 API Key 保護。

  • 開啟位置：開發者工作台 → 系統狀態 → API 目錄 → 外部 API 保護設定。
  • 可替不同外部系統建立不同 API Key，例如 ERP 同步、薪資系統、外部打卡設備各用一組。
  • 每組 Key 可個別開放員工名冊、出勤紀錄、請假資料、加班資料、外部打卡等範圍，停用或刪除後會立刻阻擋該組 Key。
  • 工作台只顯示 Key 名稱、末 4 碼、權限範圍、最近使用時間與來源 IP；完整金鑰只在新增或更換時輸入，不會再次顯示。
  • 建議外部系統使用 x-api-key header 傳入 API Key，不要把金鑰放在網址中。
  • 員工名冊端點：GET /api/employees 與 GET /api/employees/:id 會回傳完整員工欄位，包含工號、姓名、性別、國籍、部門、職稱、卡號、密碼、身分證字號、生日、到職日、離職日、備註、銀行帳戶、聯絡手機、緊急聯絡人、緊急聯絡電話、聯絡地址、戶籍地址與家庭概況；回應也會附上 fields 欄位對照，並保留 employeeId、employeeName、jobTitle 等常用別名。
  • 常用資料端點：GET /api/attendance/report?start=YYYY-MM-DD&end=YYYY-MM-DD、GET /api/leave/requests、GET /api/overtime/requests。
  • ERP 同步可優先使用短路徑：GET /api/leave-types、GET /api/leave-requests、GET /api/overtime-requests。
  • 請假與加班紀錄可加上 employeeId、status、start、end、limit 條件，供 ERP 或薪資系統分批同步。

ERP 匯出建議

  • 若 ERP 只吃每日考勤，請固定日期、工號、姓名、班別、打卡類型、狀態與來源欄位。
  • 若 ERP 要算薪資與請假，請使用包含請假明細的模板，保留假別、請假起訖、請假時數與請假單號。
  • 匯出前先用一小段日期測試，再讓 ERP 自動提取正式檔案。
  • 自訂欄位順序後不要頻繁變更，避免 ERP 解析規則失效。

12. 首次驗收清單

  • 已可開啟 http://127.0.0.1:3000/browser/。
  • 系統管理者已登入並修改預設密碼。
  • 至少一位員工被授權為完整管理者。
  • 至少一位員工被授權為開發人員。
  • 桌面共用密碼均已修改；管理者及開發人員已設定自己的個人網頁密碼，管理登入已另行啟用；使用管理端臨時密碼者已完成首次修改。
  • 員工名冊已建立或匯入，卡號與工號沒有重複或空白。
  • 班別、遠端打卡 GPS 與裝置綁定政策已確認。
  • 請假假別與個別員工的請假／加班審核主管已建立。
  • 員工可登入並完成一筆測試打卡。
  • 管理者可查詢考勤報表並匯出 CSV。
  • 請假核准後可在考勤匯出中看到請假紀錄。

  • 自動化完整資料庫備份排程已建立。
  • 操作稽核與自動化日誌可正常查看。
  • 已將首次設定後的備份檔複製到非本機單一磁碟的位置。
