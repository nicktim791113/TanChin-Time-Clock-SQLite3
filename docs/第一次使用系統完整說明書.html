2. 最高權限原則

本系統的最高權限不是單一帳號包辦全部工作，而是分成兩個核心權責：

系統管理者

獨立於員工資料之外，主要管理「誰可以用哪些角色登入」以及「管理者可操作哪些功能」。這是帳號與權限的最高入口。

開發人員

綁定員工帳號，負責系統密碼、自動化任務、操作稽核、完整資料庫備份還原、主功能頁籤排序、系統狀態與 API 目錄檢查。

第一次使用時請先登入系統管理者，建立可信任的開發人員與完整管理者帳號，再由開發人員設定備份、自動化與系統密碼。不要把日常員工帳號直接當成最高權限共用帳號。

3. 角色與預設帳密

開發人員 一般登入輸入工號 + 個人網頁密碼，登入後選擇已授權的開發人員工作台。 個人網頁密碼沒有共用預設值；桌面開發人員密碼預設 0000，不再用於網頁一般登入。 先授權角色並設定臨時網頁密碼，首次登入須修改，再設定備份與桌面開發人員密碼。
管理者 一般登入輸入工號 + 個人網頁密碼，登入後選擇已授權的管理者工作台。 個人網頁密碼沒有共用預設值；桌面管理者密碼預設 TC5128，不再用於網頁一般登入。 授權角色及功能，設定臨時網頁密碼；首次修改後，再確認管理者功能範圍。

4. 第一次開通順序

  1. 啟動桌面系統或開發環境，確認 Express 服務正常運行在 3000 連接埠。
  2. 開啟網頁版入口：http://127.0.0.1:3000/browser/。
  3. 使用系統管理者預設帳號登入，先修改系統管理者帳號或密碼。
  4. 確認員工資料是否已存在。若沒有員工資料，先建立或匯入最基本的員工名冊。
  5. 在帳號權限管理中，指定至少一位完整管理者與一位開發人員。
  6. 在「個人網頁密碼管理」選擇已授權的人員，輸入目前系統管理者密碼及臨時網頁密碼，按「設定／重設」。不會改動員工卡號或桌面密碼。
  7. 管理者／開發人員由一般登入輸入工號與臨時網頁密碼，先修改個人密碼並重新登入，再選擇工作台。開發人員設定備份，管理者建立班別、請假與報表設定。
  8. 仍可在網頁管理者安全設定修改桌面管理者密碼，或在開發人員系統設定修改桌面開發人員密碼；這些操作仍使用目前桌面開發人員密碼驗證。
  9. 建立一筆測試員工登入與打卡紀錄，確認裝置綁定與 GPS 權限是否符合公司政策。
  10. 建立一次完整資料庫備份，確認備份檔與 manifest 可成功產生。
  11. 匯出一份考勤報表，確認欄位順序、請假紀錄與 ERP 預期格式相容。

5. 帳號權限管理

帳號權限可以由「系統管理者」或「開發人員」管理。系統管理者是最適合第一次開通時使用的入口，因為它不依賴任何員工帳號。

可授權角色

  • 員工：所有員工帳號預設都保留員工登入權限。
  • 管理者：授權角色並設定個人網頁密碼後可進入管理者工作台；功能仍受權限模板或自訂權限限制。
  • 開發人員：授權角色並設定個人網頁密碼後可進入開發人員工作台。

個人網頁密碼與工作台切換

  • 一般員工可繼續使用既有工號與卡號，不需要全員重建帳密。卡號登入只能使用員工工作台。
  • 個人網頁密碼與卡號、員工基本資料的密碼欄位、桌面共用密碼分開。個人密碼為 8 至 128 字元，前後不可留空白，也不可與卡號相同。
  • 個人網頁密碼登入後先選擇授權工作台；只有員工工作台時直接進入。上方可切換工作台，後端每次重新核對權限；進入員工工作台仍須通過裝置綁定，GPS 規則不變。
  • 上方「個人帳號」可用目前個人網頁密碼、新密碼與確認新密碼修改密碼。已設定個人密碼的員工即使用卡號登入，也可在此輸入目前個人網頁密碼驗證後修改。
  • 設定／重設後，下次個人密碼登入必須先修改，不能直接使用管理功能。修改／重設會使該人員原有網頁登入與即時同步連線失效，登入最長有效 12 小時。
  • 系統管理者保持獨立入口，不使用員工個人密碼；在「登入帳號」表單修改自己的獨立帳號與密碼，修改後全部系統管理者連線須重新登入。

管理端設定、重設與查看目前密碼

  • 系統管理者工作台及開發人員工作台「系統設定」提供「個人網頁密碼管理」，可設定／重設與查回員工目前有效的個人網頁密碼，不提供歷史密碼。
  • 查看或重設前，必須輸入操作者自己的目前登入密碼；系統管理者使用獨立密碼，開發人員或管理者使用個人網頁密碼。每次操作均留稽核，但不寫入明文密碼。
  • 一般管理者須在自訂權限另勾「重設一般員工網頁密碼」或「查看一般員工目前網頁密碼」，才能在安全設定使用該功能。完整管理者模板不會自動獲得這兩項權限。受委派管理者只能操作員工角色帳號，不能重設或查看管理者、開發人員或獨立系統管理者。
  • 查回密碼顯示後可按「隱藏」，亦會於 60 秒後、切換目標、切換工作台、登出或頁面隱藏時清除，不存入瀏覽器儲存空間。
依需求提供查回密碼，代表具授權者及取得完整資料庫與金鑰備份的人可以解密目前密碼。 請限縮授權、保護主機與備份；正式對外連線應使用 HTTPS 或受控 VPN，純 HTTP 無法保護密碼與登入 Token 的傳輸。

管理者權限模板

模板 用途
無管理者權限 員工只能使用員工工作台，不進入管理者功能。
完整管理者 可使用全部管理者功能，適合公司主要負責人或系統營運主管。
人資管理者 偏向人員資料、請假、加班與報表查詢，也可依紙本核准資料補登請假或加班紀錄。
考勤管理者 偏向班別、手動補登、加班補登、考勤報表與匯出。
報表檢視者 只查看報表，不做高風險異動。
系統外觀管理者 管理主畫面、問候語、響鈴、主題與視覺相關設定。
自訂權限 逐項勾選管理者功能，適合精細分工。
請至少保留一個系統管理者帳號、一個完整管理者帳號與一個開發人員帳號。不要刪除或取消最後一個可管理權限的入口。

6. 管理者基礎設定

完整管理者登入後，建議依序設定下列內容。管理者工作台的主功能頁籤包含人員資料、安全設定、班別設定、手動補登、考勤報表、請假管理、加班管理、午餐團膳、主管指定、系統設定、響鈴設定與主題特效。

人員資料

  • 基本欄位包含工號、姓名、性別、部門、職稱、卡號、密碼、國籍、身分證字號、生日、到職日、離職日與備註。
  • 部門需先在人員資料內的「部門設定」建立並啟用，新增或編輯員工時只能從既有部門清單選擇，不再任意輸入部門文字。
  • 舊有員工與主管審核路徑中已存在的部門會自動匯入部門設定，仍被員工或主管路徑使用中的部門不可直接刪除或停用。
  • 延伸欄位包含銀行帳號、手機、緊急聯絡人、聯絡電話、戶籍地址、通訊地址與家庭狀態。
  • 匯入前先整理 CSV 欄位，避免卡號重複或工號空白。

安全設定

「員工網頁打卡權限」可逐員工勾選允許線上打卡，取消勾選後填原因、確認並儲存。需安全設定管理權限，系統管理者也有同名區域。預設維持允許；停用不影響登入、請假、加班、團膳或實體卡。後端每次打卡重新檢查，舊登入也立即受限制。

員工選取沿用紙本補登的搜尋、部門篩選及卡片多選。「選取顯示」只追加篩選中的員工，「清除」取消全名冊勾選；篩選隱藏不會停用已勾員工，須確認儲存才套用。

  • 裝置綁定預設啟用。員工第一次用網頁版登入與打卡時，系統會記錄裝置資訊。
  • 遠端打卡可要求 GPS，預設最大 GPS 誤差為 300 公尺。
  • 員工更換手機或瀏覽器時，管理者可解除舊裝置綁定。

班別與補登

  • 先建立公司實際使用的班別名稱、上班時間與下班時間。
  • 手動補登屬於高風險操作，應只開給考勤或完整管理者，並保留稽核紀錄。

系統顯示、響鈴與主題

  • 系統設定可調整主標題、副標與登入頁說明文字。
  • 響鈴設定可管理排程、自訂聲音與響鈴歷史。
  • 主題特效可管理節日特效、主題排程與自訂主題圖片。

7. 考勤與請假設定

打卡來源

系統會保存桌面端、密碼、手動補登、API、瀏覽器與請假等來源。這些來源會影響稽核與報表判讀。

請假流程

  • 網頁「我的請假紀錄」與管理者「請假紀錄」預設使用日曆，可切換月內列表、月份與篩選；點日期看明細或預填申請／紙本補登日期。管理者的「進階查詢／匯出」保留原區間查詢入口。
  • v1.23.0：管理者「安全設定」→「員工紀錄可見範圍」，或系統管理者工作台的同名區塊，可設定全體員工的請假、加班回看月數。須有安全設定管理權限，填原因並確認後儲存。N 表示本月加前 N 個月，0 表示僅本月；取消限制可回復完整歷史，升級預設不限制。
  • 員工「我的紀錄」顯示最早可查月份，較早資料請洽有請假終審／加班查看權限的管理者。這是查詢限制，不刪除紀錄；指定主管原待審與授權員工的代辦歷史仍依原授權查看，不能透過這些入口查未授權員工。
  • 日曆採台北時間，完整查詢跨月紀錄；跨日仍是同一筆 ID，明細時數為整筆儲存時數，不重算、不改寫申請或報表。詳見 docs/請假與加班日曆操作說明.md。
  • 請假類型支援小時或天數單位，可設定是否需附件、是否扣假、是否給薪與啟用狀態。
  • 請假路徑以部門對應主管，主管以員工身份登入審核，管理者再進行終審。
  • 請假可支援半小時、半天、一天與跨時段情境，系統會保存開始、結束與時數。
  • 試行期若員工已完成紙本核准，管理者可在請假管理中使用「紙本請假補登」，直接建立已核准請假紀錄，並寫入操作稽核。
  • 紙本請假補登可依部門篩選並一次多選員工，適合同一日期與時間區間內多位員工共同請假的情境，避免管理者重複輸入相同資料。
  • 若紙本請假補登輸入錯誤，請到「請假紀錄」找到該筆紙本補登，按「修正」即可帶回原資料調整；儲存後會直接更新同一筆已核准紀錄，補登編號不變，並保留修改前後完整稽核。若整筆不需要，按「作廢」即可。
  • 「修正」與「作廢」只會出現在仍為已核准的管理者紙本補登，一般員工線上申請不會出現這些按鈕；操作需要紙本請假補登權限並會留下稽核紀錄。
  • 請假與加班紀錄的「操作」欄會固定在表格右側；即使欄位較多，也不必先將表格水平捲動到最右邊，就能看到可用的「修正」與「作廢」按鈕。
  • 紙本請假補登不會取代線上申請流程；員工自行線上申請仍會依主管與管理部審核路徑處理。

加班流程

  • 網頁「我的加班紀錄」與管理者「加班申請紀錄」同樣提供日曆／列表、日期明細與原流程操作；員工的「待我審核」只查看指定本人為主管的待審紀錄。
  • 員工線上提出加班仍會依主管審核規則處理；主管替直屬員工提出的加班可自動核准。
  • 試行期若加班已完成紙本核准，管理者可在加班管理中使用「紙本加班補登」，直接建立已核准加班紀錄。
  • 紙本加班補登可依部門篩選並一次多選員工，適合同一日期與時間區間內多位員工共同加班的情境，系統會分別建立每位員工的加班紀錄。
  • 若紙本加班補登輸入錯誤，請到「加班申請紀錄」找到該筆紙本補登，按「修正」調整；系統會直接更新同一筆已核准紀錄，補登編號不變，並保留修改前後完整稽核。只需取消錯誤資料時可直接按「作廢」。
  • 已作廢的紙本補登仍可在紀錄中查核，但不會列入已核准請假、已核准加班或薪資請假／加班明細。
  • 加班核准紀錄只供查核、警示與匯出報表使用，不會直接修改打卡或出勤時間。

考勤報表與 ERP

考勤匯出模板包含薪資系統、異常稽核、報表分析、薪資含請假明細、完整格式與自訂格式。若要讓薪資與請假資料搭配得好，建議使用「薪資含請假明細」或自訂格式，並保留以下欄位：

  • 工號、姓名、部門、職稱、日期、時間、班別、打卡類型、考勤狀態、來源。
  • 紀錄種類、假別、請假開始、請假結束、請假時數、請假單號。
系統已設計讓核准請假也能成為考勤報表中的可查核紀錄，避免當天沒有打卡就完全沒有紀錄，方便後續 ERP 或薪資系統提取。

午餐團膳

  1. 管理者工作台 → 午餐團膳 → 供餐制度，設定生效日期、供餐星期、預設截止時間及全日請假提醒工作區間。初始不假設週一至週五供餐。
  2. 參加資格由管理者登記；加入後供餐日預設用餐。日曆選日期，可另外設定假日供餐、臨時停供與本日最晚變更時間。
  3. 員工工作台 → 我的午餐團膳，選日期登記不用餐或恢復用餐。已核准全日請假仍預訂時有提醒及直接取消按鈕，不自動取消。
  4. 台北時間到達截止或提前結單後，員工不可自行修改。管理者於日名單「代登／修正」填原因，直接更新同一筆登記並保留前後稽核。
  5. 先實際通知供應商，再按「結單並記錄交單」；目前餐數與已交單份數分開。後續異動顯示差額與人員，再次通知供應商後才「更新供應商交單」。

第一版僅管理午餐預訂，不是實際領餐，不計費、不連動薪資，也不自動送單。詳見 午餐團膳操作說明，包含權限、生效日期、退出、月報、備份與部署。

主管代辦

v1.22.0：指定代辦主管可多選 1 至 100 位員工及多位主管，一次套用。預設新增保留原主管；取代才以本次勾選替換原名單，空白取代需額外確認清除全部授權。填原因、勾確認並按「批量儲存主管指定」後才生效，未選員工不變。每人保留前後稽核與共同批次編號，資料過期或任一稽核失敗整批不寫入。

v1.21.2：主管指定與代辦表單使用可用全寬。員工名單可拖曳右下角或使用「名單高度」滑桿，在 100 至 1200px 間調整；三個設定名單高度分別保留於本次頁面開啟期間，重新載入恢復預設。調整高度不改勾選、授權或資料，也不觸發未儲存提醒。

v1.21.1：設定主管的員工、查看紀錄員工採用可搜尋／部門篩選的卡片單選；指定主管及代辦表單採用相同樣式多選，與紙本補登一致。請假／加班選日期後直接顯示申請欄位，不需先按「代申請」；篩選保留勾選，切換或重設未儲存內容時會先確認。

v1.21.0：主管代辦表單可多選 1 至 100 位員工，批量送相同請假、加班或午餐內容；任一人衝突、授權撤銷、資料過期或稽核失敗，整批不寫入。日曆員工只決定查看紀錄，表單勾選才決定代辦名單，每人時數並非總時數。

請假與加班本來共用部門審核路徑，現在統一移到管理者「主管指定」上方；下方仍是跨部門、多位的指定代辦主管。共用路徑沿用 admin.leave.settings，不自動給代辦權限；既有路徑、歷史審核人與紀錄不變。請假假別仍在請假管理。

  1. 系統管理者工作台的「指定代辦主管」，或管理者工作台「主管指定」，多選員工及主管、選新增或取代模式、填原因並確認批量儲存。可跨部門，員工與主管名單不可重疊（不能指定本人）；自訂管理者需有 admin.supervisors.manage 權限。
  2. 升級時授權為空，不按部門自動授權。主管以本人個人網頁密碼進員工工作台「主管代辦」，只看到明確指定的員工。不需要為全體員工重設密碼。
  3. 日曆選日期代申請請假，主管確認核准後仍送管理部終審；未終審可填原因代撤回。已核准請假不提供任意改寫入口。
  4. 加班保留員工自行申請；指定主管代申請並核准。原部門審核路徑及原直屬員工代加班功能保留。
  5. 午餐代登必填原因，遵守每日截止及結單；截止後由團膳管理者處理，不授予主管供餐制度或交單權限。

每次送出重新檢查授權、保留實際操作者與前後稽核。撤銷立即生效；刪除員工清除授權，不刪歷史申請。詳見 主管代辦操作說明及 批量代辦與網頁打卡權限說明。員工請假／加班申請的日期時間在電腦四欄、手機兩欄，其他申請規則不變。

使用電腦名稱連線

打卡鐘主機名稱為 TC-150，已在本台 Windows 驗證 http://TC-150:3000/browser/ 可用。這不是 Android／iPhone 名稱連線已驗收的證明。

現有 QNO 路由器負責分配 IP，但未找到新增內網 DNS 對照的功能；TC-Clock 尚未設定。本次未更改路由器或全公司 DNS，仍需確認其他設備可否提供名稱對照。

改用名稱需重新登入，裝置綁定可能需確認；不會重設員工卡號或密碼，也不會自動變成 HTTPS。完整設定與限制見 網頁名稱連線設定說明。

8. 開發者維運工作台

開發者工作台是系統維運的核心。第一次使用時，請不要只做帳號授權，也要完成以下維運設定。

系統設定

  • 變更桌面開發人員密碼（原系統密碼）；桌面登入、桌面管理者密碼變更與測試身份切換仍使用它。網頁一般登入已改用各自的個人網頁密碼。
  • 視需要啟用開發人員身份切換，用來測試管理者或員工流程。一般員工與管理者登入頁不接受系統密碼作為萬用密碼。
  • 設定主功能頁籤排序。開發人員可以在開發者工作台調整管理者與開發者工作台的主功能頁籤全域排序，並可還原預設。
  • 管理帳號權限。開發人員可和系統管理者一樣調整員工可登入角色與管理者功能權限。

稽核與系統狀態

  • 操作稽核紀錄可查登入、權限、打卡失敗、備份還原、密碼變更等重要事件。
  • 稽核封存可設定保留天數，預設保留 180 天。
  • 系統狀態會顯示服務狀態、連接埠、版本、資料庫位置、資料量、備份狀態、API 數量與自動化狀態。

9. 完整資料庫備份與還原

完整資料庫備份會產生 SQLite 資料庫檔與 manifest；已有個人網頁密碼時，另產生同名 .db.web-credentials.json 金鑰附檔，manifest 記錄其檔名及 SHA256。搬移時必須一起保留；缺少所需金鑰會停止還原，不覆蓋現有資料庫。核心資產 ZIP 也包含營運資料中的 WebCredentials 資料夾。

第一次備份設定

  1. 使用開發人員登入。
  2. 進入「匯出設定」的「完整資料庫備份與還原」。
  3. 設定完整資料庫備份資料夾。若未設定，系統會使用預設備份資料夾。
  4. 設定保留份數，預設為 30 份。
  5. 按下立即完整備份，確認最近完整備份清單出現新檔案。

還原規則

  • 還原前系統會先建立還原前緊急備份。
  • 來源檔需通過 SQLite 檢查與必要資料表檢查。
  • 執行還原前必須輸入確認文字：還原資料庫。
  • 還原會覆蓋目前使用中的資料庫，正式環境請先取得主管或系統負責人確認。

專案核心備份

除了網頁內的資料庫備份，專案也提供核心資產備份腳本，可打包原始碼、文件、使用者資料庫與自訂素材。

powershell -NoProfile -ExecutionPolicy Bypass -File ".\scripts\backup-core-assets.ps1"

10. 自動化任務

自動化任務目前可處理匯出、刪除與完整資料庫備份。第一次設定時建議先做「完整資料庫備份」排程，再設定報表匯出。

任務類型 可用目標 建議用途
匯出 上週打卡紀錄、上月打卡紀錄、手動補登紀錄、全部打卡紀錄、全部員工資料、全部響鈴紀錄、系統日誌。 固定產生考勤、員工或系統資料，交給 ERP 或內部稽核使用。
刪除 依系統允許的清理目標執行。 清理特定歷史資料。正式使用前要先確認保留政策。
完整資料庫備份 任務目標欄位會隱藏，由系統固定使用完整資料庫備份目標。 每日或每週建立完整資料庫備份，是最重要的自動化保護任務。
設計上「完整資料庫備份」不應出現在匯出或刪除的任務目標裡；只有任務類型選完整資料庫備份時，系統才會在後端固定使用備份目標。

11. API 與 ERP 匯出

API

系統提供外部 API，可查詢員工、打卡紀錄、考勤報表、請假申請紀錄、加班申請紀錄，也可建立 API 打卡。這些 API 需要先由開發人員工作台啟用，並使用多組 API Key 保護。

  • 開啟位置：開發者工作台 → 系統狀態 → API 目錄 → 外部 API 保護設定。
  • 可替不同外部系統建立不同 API Key，例如 ERP 同步、薪資系統、外部打卡設備各用一組。
  • 每組 Key 可個別開放員工名冊、出勤紀錄、請假資料、加班資料、外部打卡等範圍，停用或刪除後會立刻阻擋該組 Key。
  • 工作台只顯示 Key 名稱、末 4 碼、權限範圍、最近使用時間與來源 IP；完整金鑰只在新增或更換時輸入，不會再次顯示。
  • 建議外部系統使用 x-api-key header 傳入 API Key，不要把金鑰放在網址中。
  • 員工名冊端點：GET /api/employees 與 GET /api/employees/:id 會回傳完整員工欄位，包含工號、姓名、性別、國籍、部門、職稱、卡號、密碼、身分證字號、生日、到職日、離職日、備註、銀行帳戶、聯絡手機、緊急聯絡人、緊急聯絡電話、聯絡地址、戶籍地址與家庭概況；回應也會附上 fields 欄位對照，並保留 employeeId、employeeName、jobTitle 等常用別名。
  • 常用資料端點：GET /api/attendance/report?start=YYYY-MM-DD&end=YYYY-MM-DD、GET /api/leave/requests、GET /api/overtime/requests。
  • ERP 同步可優先使用短路徑：GET /api/leave-types、GET /api/leave-requests、GET /api/overtime-requests。
  • 請假與加班紀錄可加上 employeeId、status、start、end、limit 條件，供 ERP 或薪資系統分批同步。

ERP 匯出建議

  • 若 ERP 只吃每日考勤，請固定日期、工號、姓名、班別、打卡類型、狀態與來源欄位。
  • 若 ERP 要算薪資與請假，請使用包含請假明細的模板，保留假別、請假起訖、請假時數與請假單號。
  • 匯出前先用一小段日期測試，再讓 ERP 自動提取正式檔案。
  • 自訂欄位順序後不要頻繁變更，避免 ERP 解析規則失效。

12. 首次驗收清單

  • 已可開啟 http://127.0.0.1:3000/browser/。
  • 系統管理者已登入並修改預設密碼。

  • 桌面共用密碼均已修改；管理者及開發人員已設定自己的個人網頁密碼，並完成首次修改。
  • 員工名冊已建立或匯入，卡號與工號沒有重複或空白。
  • 班別、遠端打卡 GPS 與裝置綁定政策已確認。
  • 請假假別與部門主管審核路徑已建立。
  • 員工可登入並完成一筆測試打卡。
  • 管理者可查詢考勤報表並匯出 CSV。
  • 請假核准後可在考勤匯出中看到請假紀錄。
  • 完整資料庫備份可手動建立，且最近備份清單有紀錄。
  • 自動化完整資料庫備份排程已建立。
  • 操作稽核與自動化日誌可正常查看。
