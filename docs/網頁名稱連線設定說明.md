# 使用電腦名稱連線網頁版

日期：2026-10-03；配合版本：v1.20.0。這是內網設定說明，不代表 TC-Clock 已完成設定。

## 已確認的狀況

- 打卡鐘主機 IP 為 `192.168.0.150`，Windows 電腦名稱為 `TC-150`。本次在開發電腦的 Windows 環境驗證 `http://TC-150:3000/api/browser/health` 可連線，網頁入口為 `http://TC-150:3000/browser/`。
- 這只驗證本台 Windows 的名稱解析，不保證所有電腦、Android 或 iPhone 都能用同一名稱。
- 已登入的 QNO 路由器負責分配 IP（DHCP）。檢查目前設定頁未找到可新增「TC-Clock → 192.168.0.150」的內網 DNS 對照功能；名稱查詢也未得到這筆對照。不代表所有同品牌型號都不支援。
- 本次沒有更改路由器 DNS、DHCP、主機名稱、WAN、轉發或登入密碼，沒有重新啟動路由器。`TC-Clock` 尚未可用，手機名稱連線尚未驗證。

## IP 分配與名稱對照是不同功能

路由器分配 IP，像分配座位號碼；名稱解析則要有一份「TC-Clock 是哪個 IP」的對照表。設備全由同一台路由器發 IP，不代表它也能新增這份名稱對照。路由器頁面的「主機名稱」是路由器自己的名字，不能拿來代替打卡鐘的 DNS 對照。

## 電腦現在怎麼使用

在網址列輸入完整網址 `http://TC-150:3000/browser/`。若該電腦無法解析名稱，先用原 IP 網址，不改既有安全設定。這不是對外網際網路網址，需在可連公司內網的環境使用。

改用名稱會成為不同的網站來源。瀏覽器不共用原 IP 網址的登入、裝置識別或儲存資料，可能需要重新登入，啟用裝置綁定時可能需管理者確認／重新綁定。不是員工帳號、卡號或個人密碼被重設；原網址仍可保留直到新入口驗收完成。

## 若要所有裝置都用 TC-Clock

1. 先確認其他網路設備的品牌、型號與用途，例如 NAS、另一台路由器或伺服器；不要求員工自行判斷是否有 DNS。確認是否可提供長期運作、受維護的內網名稱對照服務。
2. 保留打卡鐘的固定 IP 或 DHCP 固定租約，避免名稱指向過期地址。原主機目前在現有 DHCP 配發範圍外，不要把它隨意改入配發池。
3. 在支援的內網 DNS 建立打卡鐘名稱／別名，使用公司內網網域的完整名稱作為跨平台入口；單字短名稱 `TC-Clock` 能否自動補網域要逐台驗證，不能只測 Windows 就視為手機可用。
4. 先在少量測試裝置手動指定這個 DNS，確認內網名稱與一般上網都正常，再安排維護時間、備份路由器設定，最後才考慮調整 DHCP 配發的 DNS。路由器仍可繼續發 IP，不需要換掉 DHCP。
5. DNS 服務必須處理其他一般網址解析。不能把全公司 DNS 直接指向目前只提供打卡 HTTP 的電腦，否則大家可能無法上網。服務應具備固定位置、自動啟動、存取限制及備援規劃。
6. 驗收 Windows、Android、iPhone、不同 Wi-Fi／VLAN；手機的私人 DNS、VPN 或其他安全 DNS 設定可能不使用內網 DNS，需納入確認，不要求全體員工關閉安全功能。

目前軟體使用連接埠 3000，所以名稱設定後仍需 `:3000/browser/`。若希望直接輸入短名稱就進入，還要另外規劃標準 HTTP／HTTPS 入口與重新導向，不只是新增名稱對照。

## 安全與部署邊界

- 不開啟 WAN 連接埠轉發、不使用公開 DNS 洩漏私人位址，也不安裝不明來源 DNS 工具。
- 改成名稱不會把 HTTP 自動變為 HTTPS，也不解決手機 GPS 的安全來源要求；跨網路及正式安全傳輸仍需受控 HTTPS／VPN 規劃。
- DNS／路由器設定不在 SQLite 或 GitHub 裡。需另外保存內網設定與回復步驟，不能以 GitHub push 當作網路設定已完成。
- 本次查詢打卡鐘健康檢查仍為 v1.18.0，開發原始碼發版不會更新另一台正在執行的打卡鐘；須按部署還原說明在真正服務主機升級並重新啟動。
