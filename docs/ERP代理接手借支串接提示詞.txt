請接手正式 Tan Chin ERP 的「考勤借支申請串接」。先閱讀隨附的《ERP借支串接交接說明.md》。考勤 v1.34.0 API 已實作並通過隔離測試，本機完整測試 313／313 通過；本文件就是目前已實作的契約，可依此開發 ERP consumer。ERP 端仍待修改及驗證；TC-150 的目前安裝版本須在正式連線時核對；正式連線前先核對考勤主機版本與 API 回應，不要把本地實作完成當成已部署。

請先確認你正在使用正式 ERP 1.149.0.0 或後續版本對應的最新專案、Git 分支與部署來源。不要使用 D:\Developer\Tan Chin ERP System 中的 2026.05.10 舊副本。正式頁為 http://192.168.0.113:3200/#/attendance-sync-center。

已核對的正式畫面：ERP 考勤同步中心會用已儲存的來源位址與 API Key 拉取員工、打卡、請假、加班；employee-benefits 已有借支帳（日期／金額／備註）、FIFO 沖抵，以及月份還款金額取代機制；薪資總表有借支檢查／預覽並取代 advanceDeductionAmount；已鎖期別唯讀。請從目前正式程式再核對內部模型、服務與權限，不另做一套重複財務帳。

同一版考勤另新增多段請假，請一併閱讀本文件附錄 A 並調整 ERP 請假 consumer。GET /api/leave-requests 與 /api/leave/requests 的外層格式維持，單筆新增 dateSelectionMode="explicit_segments"、leaveSegments:[{id,date,startAt,endAt,hours}]。startAt/endAt 是每段毫秒時間戳，hours 為實際請假量。不得用申請外層 start_at/end_at 或 startAtIso/endAtIso 當成連續請假，不可把未選日期／午休空檔計入。舊 legacy_range 與 explicit_dates 各保留原語意；未知模式須攔下核對。ERP 未完成測試前，不可宣稱已正確同步或計薪。

目標：考勤端每月 15 至 20 日讓員工填寫借支金額，日期及上限可由活動設定調整，僅由管理部審核。ERP 新增借支申請的讀取、來源暫存、去重與待處理清單，之後依既有借支／薪資流程處理。考勤端入口為 GET /api/salary-advance-requests，scope 為 salary_advances。這是修訂事件 feed；data 同一單號會因送出、核准、取消而多次出現。以 cursor + cursorEventId 增量續讀，分頁另固定 untilCursor + untilEventId；meta 回 nextCursor／nextCursorEventId。缺檢查點或還原導致 UUID 不符不可忽略。實際狀態、欄位及分頁仍請與考勤端發布契約對齊。

必守邊界：
1. 核准申請不等於已發放，也不等於應扣薪。同步 approved 只暫存來源；除非使用者另外明確定義流程，不能自動入借支帳或修改薪資。
2. 工號使用字串，保留 "085" 的前導零；不得以姓名猜測對應。
3. 以穩定來源連線識別 + requestId 去重，保存 revision 與來源歷史。重讀三次結果一致，不累加金額。
4. 更正／取消要能同步；已發放或已入薪資的資料收到來源變更時轉待核對，禁止直接覆寫、硬刪或重複發放。
5. 沿用既有借支帳、FIFO、月份還款取代、薪資借支預覽後取代機制；不可同步一次再扣一次。已鎖薪資期別不改。
6. 既有人工借支與調整不得被同步抹掉。申請來源與借支／薪資紀錄要有可追溯關聯。
7. API Key 僅在 ERP 後端安全取得；不放網址、不輸出明文。財務查看、審核、發放與薪資調整權限分別核對。
