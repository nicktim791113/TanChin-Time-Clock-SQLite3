# 員工假別額度管理

日期：2026-10-17；適用版本：v1.28.0。

## 入口與權限

- 管理者工作台 → 請假管理 → 假別額度。完整管理者、人事管理者可設定；自訂權限分為 `admin.leave.balances.view`（查看／匯出）及 `admin.leave.balances.manage`（設定／匯入）。設定權限包含查看，身份模擬不能異動。
- 系統管理者工作台另有「假別額度」區塊。
- 員工「請假申請」可看本人當年度額度。主管「主管代辦 → 請假」可看目前查看的指定員工、所選月份年度餘額，不能調整；非代辦員工無權查詢。

## 年度及工時

目前額度帳依曆年保存，每年 1 月 1 日至 12 月 31 日，預設每日 8 小時。管理者可設定新額度的每日換算工時（1 至 24 小時）；每筆員工／假別／年度保留建立時工時，後續修改制度不會重算既有額度。各人可有不同特休天數；不自動按年資核給、結轉或計算未休工資。

v1.28.0 起，只有選擇特休才顯示特休年度記帳說明；事假、病假等不顯示「年度制度」。新額度換算工時是各假別共用欄位，仍可設定；人工轉入／調整並非自動結轉。年資給假、週年權利帳與年度結算方向另見 [設計草案](年資給假與年度結轉設計草案.md)，本版尚未實作。

假別設定的給薪方式可選全薪、半薪、無薪；此欄是資訊標記，不影響本頁額度的扣抵比例，也不執行薪資計算或扣薪。舊資料依原有薪／無薪值保留，不自動更改既有病假。

所有假別都能個別設定額度。已設定額度的假別依其額度帳核計；「扣額度」假別的新申請，即使尚未設定額度，也須確認實際時數。未設定不是零額度，額度不足提示負數，不直接禁止提出申請。

## 首次建置

1. 備份真正打卡鐘主機的完整資料庫與 WebCredentials。
2. 選年度與假別，勾選 1 至 100 位員工，填額度、結轉、調整及原因。個別設定只勾選一人。
3. **全年總額**：填全年度原始核給天數，扣抵起日固定 1 月 1 日。既有該年度核准單列入已使用、待審單列入預占，不改原請假單，也不另外建立重複扣抵。
4. **期中剩餘額度**：已在其他帳冊結算過時，填截至扣抵起日前一日的剩餘天數，例如起日 2026-10-15，輸入 10 月 14 日結算後剩餘。只扣起日以後的請假，不再重扣之前的舊單。舊單跨起日須補每日扣抵分配。起日前請假的後續取消／修正不會自動改動這個人工剩餘基準，管理者須調整額度並記錄原因。
5. 預覽會列出核准、預占及可用額度。確認無重複計入後，勾選確認並儲存。設定是取代所選員工當年度數值，**不是每次加發同額天數**；其他人不變。

可用小時 = 額度天數 × 該年度每日工時 + 結轉小時 + 調整小時 − 已核准小時 − 待審預占小時。

## Excel 作業

1. 在年度及假別選擇後「匯出 Excel 填寫表」，包含「假別額度」、「目前餘額」及「填寫說明」三頁。
2. 工號保持文字格式，保留前導零。填額度天數、結轉／調整小時及每列設定原因；額度空白列不匯入，`0` 是明確設定零額度。保留身份、假別及版本欄位。
3. 使用 .xlsx，不接受公式或密碼保護檔；最大 5 MB、解壓縮總內容 20 MB、最多 1000 筆。整批驗證員工、姓名、假別、年度、日期、時數、重複鍵及版本。
4. 選取檔案後只會預覽，不會立即儲存。檢查全部列並勾選確認後一次儲存；任一列或稽核失敗全部回滾。
5. 額度、制度或名冊在匯出後異動，舊版檔案會拒絕覆蓋。重新匯出並轉填資料，不可自行修改版本欄來略過檢查。一般請假異動不會讓填寫中的 Excel 作廢，匯入預覽會讀取最新使用／預占；預覽後請假又異動時，儲存會要求重新預覽，避免用舊餘額確認。

## 請假扣抵與歷史安全

- 主管待審及管理部待審都只預占一次。管理部終審核准轉為使用；撤回、駁回釋放。主管代辦請假仍須管理部終審，不能提前列為使用。
- 紙本補登已核准立即列使用；修正更新同一個原單 ID，依修正後員工／假別／日期／時數重新核計差額；作廢釋放，不新增取消副本。
- 額度不受員工紀錄可見月數限制，統計完整適用期間；歷史明細權限仍保持原限制。
- 新的跨日額度請假須填「每日實際時數」，格式 `YYYY-MM-DD=小時`，每日一列；加總等於整筆時數，不得重複日期。管理者補登及主管批量代辦使用同一格式。非工作日不列，午休自行排除，不推定週末一定不上班。
- 新的跨年申請必須有每日分配，依日期扣不同年度；其中一個年度沒額度時仍不阻擋送件，須由管理者補設定。
- 舊單同年度內依原 `duration_hours` 核計，不重算或改寫時數。跨年度、跨首次扣抵起日或無有效時數的舊單顯示「待確認」，可用餘額暫不給確定數字。
- 「舊單／跨年每日扣抵分配」用原請假單編號填每日時數、原因及確認，只新增扣抵分配與稽核，原單狀態、ID、時數、日期及審核人不改。原單沒有正確時數時，先依原請假管理流程處理，不擅自修正資料。
- 每次設定保留前後數值、操作者、原因及批次識別。請假建立、審核、撤回、紙本修正／作廢及稽核同交易；稽核失敗不局部保存。
- 刪除員工會移除其額度設定，並保留隔離標記；重用同工號不會承接原人的額度或已用時數。原請假單仍保留供管理端查核。

## 備份與部署

v1.26.0 新增 `leave_entitlements`、`leave_entitlement_charges`、`leave_entitlement_employee_epochs` 表及制度 settings。既有請假表不新增欄、不更新原資料。完整 SQLite 備份包含新資料；不要直接降版後繼續作業，舊版不更新每日扣抵分配。需回復時還原升級前完整備份並確認停止期間異動。

v1.26.0 將 Excel 套件依 [SheetJS 官方安裝來源](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/) 更新為 0.20.3，固定官方 tarball URL 與 lock integrity；當次只更新此相依套件及其移除的子相依，不做全面 `npm audit fix --force`。v1.28.0 未變更相依套件。

遵循 `docs/更新紀錄.md`、`docs/快速部署還原說明.md` 與完整手冊，先 Git clean / pull，再修改、版本、測試、建置、核心備份、檢查上傳項目、commit / push。Git 不加入營運 SQLite、LOG、金鑰、node_modules、dist 或 .env。GitHub push 不等於正式主機已部署；更新打卡鐘主機並重啟，確認 `/api/browser/health` 的 `data.appVersion` 為 `1.28.0`，再首次設定額度。
