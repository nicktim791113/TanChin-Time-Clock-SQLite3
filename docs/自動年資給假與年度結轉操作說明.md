# 自動年資給假與年度結轉操作說明

日期：2026-10-17；適用版本：v1.29.0。

本功能已實作「依已核對年資計算 → 預覽 → 授權人確認入帳 → 到期或離職結算」，入口名稱為「年資特休制度」。這裡的自動是依規則計算，不是每日、生日、到職週年或元旦背景排程；未按確認，不會自行發給、遞延或結清額度。安裝新版也不會替既有員工直接建立權利帳。

本功能保存完整權利來源、年度配置、精確分數及異動。未休工資僅產生「待未休工資處理」記錄，沒有核薪、付款或自動扣薪功能。公司仍需核對適用制度、員工資料、協商依據及通知作業。

人工假別額度的表單、Excel 與每日扣抵分配，見 [員工假別額度管理說明](員工假別額度管理說明.md)；計算及實作決策見 [年資給假與年度結轉設計草案](年資給假與年度結轉設計草案.md)。

## 1. 入口與權限

管理者工作台 → 請假管理 → 假別額度 → 選擇特休 →「年資特休制度」。系統管理者可從其假別額度區塊進入；只有新增特休權限、沒有舊人工額度權限者，進入假別額度入口時直接顯示年資特休工作區。

| 工作 | 權限與限制 |
| --- | --- |
| 查看全員權利、制度、給假試算及匯出 | `admin.leave.balances.view`，或下列任一特休操作／額度調整權限。查看不等於可入帳 |
| 建立制度、核對及新增年資版本 | `admin.leave.entitlements.policy.manage` |
| 核准給假入帳 | `admin.leave.entitlements.grant` |
| 確認年度／離職結算與協商遞延 | `admin.leave.entitlements.close` |
| 預覽及確認精確額度調整 | `admin.leave.balances.manage`；給假或結轉權限不能代替 |
| 員工查看 | 只看自己的已入帳權利、配置、異動及計算快照 |
| 主管查看代辦員工 | 主管本人的個人網頁密碼登入員工工作台，且目前仍有該員工的明確代辦授權；刷卡登入不能取得代辦資料 |

新增的制度、給假、結轉三項權限不自動加給既有「完整管理者」。系統管理者可先建立制度並透過帳號權限明確委派；未授權者即使直接呼叫 API 也會被拒絕。身份模擬禁止所有制度、年資、給假、結算及調整異動。主管明細入口及員工明細入口均為唯讀，沒有調整按鈕。

## 2. 先理解畫面上的不同數字

| 名稱 | 意義與注意事項 |
| --- | --- |
| 完整已取得來源／權利批次 | 依半年、滿年資格事件產生的完整權利；例如滿半年 3 日與滿一年 7 日分開保存 |
| 本年度配置 | 依公司確認制度，配置到所選年度可使用的部分；不是完整來源權利的替代品 |
| 配置至後續年度（已取得） | 已取得的同一來源分配到後續年度，已列在權利帳；不能再當作一次協商遞延加發 |
| 未達資格日（僅預估） | 試算日尚未取得的資格事件，供檢查未來情況，不會提前入帳 |
| 已認列／無新增 | 同一資格事件已發給；重複試算不再發一次 |
| 待審預占 | 尚待主管或管理部審核的時數，先保留可用額度；終審核准後轉為已休 |
| 可用 | 扣掉已休、預占、結算及相關調整後的精確餘額；有未確認扣抵時可能不顯示確定值 |
| 期初接管 | 經人工對帳後帶入的未休小時；不是重新發一次以前的全部法定天數 |
| 協商遞延 | 原來源可用額度移至後續期間，保留原來源及同意依據；不是兩邊同時保留完整可用額度 |
| 待未休工資處理 | 未休權利已列入後續薪資核對，狀態為 `wage_pending`；沒有薪資金額或付款完成的含義 |

總覽的「已給小時」不是可用餘額，也不是含所有調整與遞延的總數。核對時同時查看明細中的來源、調整、已休、預占、結算及可用小時。

## 3. 第一次使用的順序

1. 先依專案備份及部署文件確認正式主機資料庫已備份，核對軟體版本。備份與部署由正式發布流程處理，本功能頁面不會代為完成。
2. 在員工名冊核對到職日及已知離職日；另準備認列年資、留停／復職、工時型態、原額度及已休對帳資料。
3. 在「制度版本」選定特休假別、週年／曆年、折算及小數策略，記錄協商依據。
4. 在「年資核對」逐人設定版本、生效日、工時及接管基準。接管前已取得的來源不會整批重發，已核對餘額由期初小時帶入。
5. 在「給假試算」選制度、配置年度、基準日及 1 至 100 位員工。展開每人計算，先處理所有阻擋項目。
6. 具給假權限者在同一登入身份重新試算、勾選影響範圍確認後「核准給假入帳」。查看權限者的預覽不能交由另一個登入直接確認。
7. 在「權利總覽」核對餘額及明細。年度／來源期間到期或員工離職，再進入「年度結算」處理；時間到達本身不會自動結算。

## 4. 共用按鈕與使用方式

| 欄位／按鈕 | 用途 |
| --- | --- |
| 查看年度 | 切換總覽與匯出年度，支援 2017～2100；不是發給日期，也不會發給額度 |
| 返回人工假別額度 | 回到原人工表單；只有具舊額度查看或設定權限者看得到 |
| 重新整理 | 讀取最新名冊、制度、年資與權利資料。若有未儲存輸入或預覽，會先詢問是否捨棄 |
| 六個分頁 | 權利總覽、制度版本、年資核對、給假試算、年度結算、精確調整；依權限顯示 |
| 說明 | 顯示目前分頁的整體操作、欄位、按鈕及注意事項 |
| 匯出精確 JSON | 匯出查看年度的餘額、結算及已入帳來源／計算快照，保留精確分子分母。不是可直接還原的資料庫備份 |
| 匯出核對 CSV | 匯出查看年度的額度核對表；物件欄位以 JSON 文字保存。試算未入帳內容不在正式匯出內 |
| 展開列／明細 | 點擊摘要列展開資格事件、計算式、精確值或本次影響；再點一次收起 |
| 取消預覽 | 清除待確認結果，不寫入權利帳；需要入帳時重新試算 |

切換年度、分頁、工作區、返回或登出時，尚有草稿會提醒捨棄。修改試算條件會使原預覽失效；收到其他工作台的相關資料異動時，輸入保留但須重新整理並重新試算。送出期間按鈕暫停使用，避免重複操作。

## 5. 六個分頁逐項說明

### 5.1 權利總覽

上方統計列出制度版本數、可見人員數、權利帳數及所選年度的結算紀錄數。下方每位員工列出年度、已給、已休、待審預占及可用小時；「查看明細」開啟唯讀視窗。總覽下方同時列出制度版本、生效日、期間、折算及精度，便於辨識適用規則。

週年制的年度總覽是「與所選年度相交來源的全期餘額」，包含這些來源在其他年度發生的使用／預占，不等於該曆年的請假發生量。需要年度發生量時應依請假日期查紀錄。若交集來源適用不同正常日工時，日數逐來源用自己的工時換算後相加，不能拿合計小時除以最新工時；請搭配各來源明細及回應中的 `summaryScope` 核對。

明細視窗的「明細年度」可切換年度；展開權利快照、來源配置、結算及異動紀錄，核對取得日、精確分數、使用期間和原始來源。「關閉」或 Esc 返回工作區。尚無快照表示尚未在系統入帳，不表示員工沒有法定休假權利。

### 5.2 制度版本

| 欄位／操作 | 填寫及效果 |
| --- | --- |
| 制度名稱 | 最多 100 字，供預覽及歷史快照辨識 |
| 生效日期 | 此制度版本適用的資格取得日起點；不得早於 2017-01-01，新版本須晚於同假別舊版本 |
| 特休假別代碼 | 例如 `annual`；必須是實際存在、已啟用且扣額度的假別，並確認確實為特休。系統不會把事假或病假自行改成特休 |
| 特休制度 | 曆年制或週年制；已有權利帳不能直接切換期間制度 |
| 折算基礎 | 曆月比例或實際日數；曆年配置依該方法分段，須先核對公司協商依據 |
| 小數處理 | 保留精確原值，或同年度分段加總後無條件進位至小數第 1 位 |
| 協商／制度依據 | 最多 500 字，可填已確認文件名稱、日期或編號；不是點勾選即代替員工協商 |
| 建立版本原因 | 最多 500 字，記錄為何新增這個制度 |
| 兩個確認欄 | 分別確認假別與制度內容、確認新增版本而不覆寫舊版 |
| 建立制度版本 | 保存版本及稽核，尚未發給任何員工額度 |

已發給的資格事件不會因建立新政策而重新發給或換掉原規則。新政策生效日不得回溯覆蓋已入帳來源。若同一配置年度將混用正常工時或進位規則，給假會阻擋並要求專用對帳，不能用新增版本強行混算。

### 5.3 年資核對

| 欄位／操作 | 填寫及效果 |
| --- | --- |
| 核對員工 | 選擇本次逐人核對對象，載入已保存的資料與版本歷程 |
| 本次核對版本生效日 | 首次必須與接管起日一致，先建立基準再新增後續版本；已有入帳者必須提供晚於舊版本的日期，不能覆寫舊版 |
| 認列年資起算日 | 實際核實的連續服務年資起點；可與名冊到職日不同，但須有公司核對依據，不能以空白或今日自動補值 |
| 正常每日工時 | 全時或相同工作日數的部分工時使用實際核實工時，允許 1～24 小時 |
| 比例換算基準工時 | 選比例型部分工時時顯示此名稱；通常用核實的全時基準工時。已在比例折減後，不再另用減少工時重複折減 |
| 工作型態 | 全時工作、部分工時：相同工作日數、部分工時：比例計算 |
| 權利比例 | 十進位或分數，例如 `1`、`0.5`、`1/2`；只有比例型可使用大於 0 且不超過 1 的其他比例。其他型態送出時固定為 1 |
| 比例計算依據 | 比例型必填，最多 500 字，說明已核對的正常工時及折算來源 |
| 不計年資期間 | 每行 `起日,復職日,原因`，例如 `2026-01-01,2026-02-01,留職停薪`；起日含、復職日不含，不可重疊或倒置 |
| 權利接管起日 | 不早於實際到職日及 2017-01-01。接管前已取得來源不再自動發給，請先對帳 |
| 期初未休餘額 | 填精確小時，可用 `1/3`。是接管前已核對的剩餘，不是過去全部原始核給日數 |
| 期初餘額使用迄日 | 此日期包含在可用期間內；需在接管日起至其後一年內。內部換成翌日不含的邊界 |
| 期初對帳來源與核對依據 | 畫面必填；記錄原帳冊、已休及待審處理方式。已有人工額度或期初餘額時後端也強制檢查 |
| 儲存原因 | 記錄本次核對或修訂原因，最多 500 字 |
| 年資／接管／保存確認 | 分別確認年資及工時、期初已對帳不重發、確認保存 |
| 特殊日期人工核對 | 適用月底或 2 月 29 日等特殊日期者，先核對試算規則再勾選；未核對的特殊情況會阻擋入帳 |
| 儲存核對資料 | 保存資料及稽核；不是給假按鈕。下面列出版本生效日、起算日、工時、比例與原因 |

已入帳後，接管日期、期初小時、使用迄日及對帳來源固定，畫面唯讀。正常工時與比例依每個資格取得日適用的年資版本凍結，既有批次不回寫；但同一配置年度不能混用不同正常工時或進位規則。

若修訂會移動既往資格日、改變已取得日數／小時或使既往來源失去資格，系統保存「待核對提案」並顯示警示，原有效版本保持不變，後續給假封鎖。這種回應不是新版本生效成功。專用歷史對帳目前沒有一鍵覆寫入口；需要先確認歷史權利與處理方式。只做額度加減不會自動清除年資待核對狀態。後續有效修訂通過核對後才解除封鎖。

### 5.4 給假試算

| 欄位／按鈕 | 用途 |
| --- | --- |
| 制度版本 | 選已保存且涵蓋資格取得日的制度 |
| 配置年度 | 查看與計算該年度的來源分攤；不能只靠改年度重複發同一資格事件 |
| 資格判斷基準日 | 判斷哪些資格已取得。可填未來日期試算，但未來基準日禁止確認入帳 |
| 試算與給假原因 | 隨確認批次保存，最多 500 字 |
| 搜尋工號／姓名、部門篩選 | 縮小畫面名單；不取消先前已選的人員 |
| 個人勾選、選取顯示人員 | 加入本次名單，最多 100 人；操作前留意「已選」及「顯示」人數不同的情況 |
| 清除選取 | 移除全部已選員工，不刪除資料，也不清空搜尋條件 |
| 產生給假試算 | 產生暫存預覽，尚未寫入給假、年資或權利流水 |
| 預覽確認欄、核准給假入帳 | 具給假權限者核對全部列後一次確認；任何一位被阻擋時整批不入帳 |

逐人展開預覽，核對法定已取得來源、原始配置、處理後日數、進位差額、本年度新增小時、完整來源入帳小時、後續年度配置、已認列小時與未到資格預估。再展開資格事件與年度分段，可看到年資門檻、不計年資日數、取得日、法定級距、比例、權重、精確分數及公式。

預覽綁定目前登入及操作者，保存期限 30 分鐘，伺服器重啟後須重做。名冊、年資、制度、額度或請假資料在確認前變更，舊預覽會拒絕入帳。確認重試使用同一請求識別碼，只返回既有結果；不能換內容沿用識別碼。網路中斷時先重新整理核對，不用再次輸入相同人工額度補發。

### 5.5 年度結算

| 欄位／操作 | 用途 |
| --- | --- |
| 結算年度 | 年度終結須等於所選來源配置年度；契約終止須等於結算基準日的年度 |
| 結算基準日 | 判斷來源是否到期或已離職；未來基準日不能確認 |
| 結算情境 | 「年度終結」列所選年度來源；「契約終止」另選員工並列出其全部來源，包括後續年度配置 |
| 離職員工 | 契約終止時必選，須先在名冊確認最後在職日；不能只以目前年度總覽餘額作離職結算上限 |
| 結算原因 | 說明本次處理依據，最多 500 字 |
| 展開來源、納入本次結算 | 檢查期間、原始來源、已休及預占，再逐批勾選。本次處理該批全部可結算餘額，不輸入任意部分數字 |
| 未休處理方式 | 預設「列待未休工資處理」；可遞延來源才提供「協商遞延至次年度」 |
| 同意日期、同意證據／文件編號 | 遞延逐筆必填，同意日不得晚於結算基準日；一般描述不代替實際協商資料 |
| 預覽年度結算 | 顯示每筆精確小時、日數、原期間、處理方式及阻擋原因 |
| 確認欄、確認年度結算 | 具結轉權限者確認後一次寫入來源扣除、遞延或待工資記錄及稽核 |

以下情況須先處理，不能強制結算：尚未到期且未離職、待審預占、舊單跨來源／年度卻沒有每日分配、來源有未覆蓋時數、沒有正數餘額、同意資料不全、重複遞延、結算日尚未取得來源、年資修訂仍待歷史核對，或名冊到職／離職日與已核對版本不同。更改名冊離職日後，先在「年資核對」新增有效版本再結算。已離職員工即使選「年度終結」也不能再遞延；契約終止必須選齊同一權利帳內尚有餘額或預占的全部已取得來源，包含後續年度配置，漏選會阻擋整批。

遞延後原來源餘額扣除，新來源自原配置期間結束日起，至下一年相同日期前使用；請假會先扣適用的遞延批次。遞延到期或離職仍未休，列待未休工資，不能再遞延一次。撤回／作廢舊請假會回到原來源；若該來源已結算，需重新核對新增剩餘，不會自動加到下一年造成雙重額度。

### 5.6 精確調整

| 欄位／操作 | 用途 |
| --- | --- |
| 調整來源批次 | 依工號、年度、類別及可用小時選擇要更正的特定來源，不覆寫整人年度總額 |
| 精確調整小時 | 正數加、負數減，支援十進位及分數，例如 `0.8`、`-0.125`、`1/3`；不可為零 |
| 調整原因與依據 | 最多 500 字，記錄對帳與修正理由 |
| 預覽精確調整 | 列調整前可用、本次差額及調整後可用，以及精確分數 |
| 確認欄、確認精確調整 | 具獨立額度管理權限者確認後記錄差額及流水，保留原給假與請假資料 |

負調整不能移除已休、預占或已結轉的權利，也不能使來源可用變負。來源有待確認每日扣抵時先完成分配。此功能不改名冊到職日、資格事件或歷史制度版本，亦不會核定工資。

## 6. 計算規則、精度與例子

### 年資與取得日

日期採 Asia/Taipei 純日期，計算資格不用「今年減到職年份」或以毫秒除以 365。已確認不計年資期間按實際日數移動各資格門檻；最後在職日包含當日，取得日晚於最後在職日者不新增該來源。月底及閏日以原始日期錨點及目標月月底規則計算，須透過特殊日期確認核對。

| 已符合年資 | 本次完整基準日數 |
| --- | ---: |
| 未滿 6 個月 | 尚未取得此法定資格 |
| 滿 6 個月 | 3 |
| 滿 1 年 | 7 |
| 滿 2 年 | 10 |
| 滿 3、4 年 | 每年 14 |
| 滿 5～9 年 | 每年 15 |
| 滿 10 年起 | 16 日起，每滿一年再加一日，最高 30 |

這是勞基法第 38 條的年資級距；公司優於法令的加給需另以可追溯調整處理，不能拿來抵銷法定來源。半年與滿一年為不同批，不能把 3 日扣掉後只補 4 日。[勞動基準法第 38 條](https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=N0030001&flno=38)

### 週年與曆年配置

週年制保留半年資格取得後六個月、其後各週年權利期間。曆年制先保留同樣完整來源，再依約定折算成年度配置；它不會把未達資格日的權利預先當成已取得。可協商的行使期間及符合資格後通知義務，見 [勞基法施行細則第 24 條](https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=N0030002&flno=24)。

```text
來源在某年度的原始日數 = 完整來源日數 × 年度交集權重 ÷ 完整來源期間權重
年度原始日數 = 同年度各來源精確分段總和
新配置小時 = 來源適用的日數 × 已核定正常日工時
```

曆月比例：完整曆月權重為 1，不滿月按該月涵蓋天數／該月天數計算。實際日數：以真實交集天數及完整期間天數相除，包含閏年差異。半年來源使用它自身六個月的分母，不錯除 12。折算方法及進位選項是產品支持的公司約定，法令並未指定只能用這一個算式。

**折算交集和可使用期間不同。** 原始折算區段保存在 `sourceIntersectionStart`／`sourceIntersectionEndExclusive`。曆年配置可使用期間為 `max(來源取得日, 當年1月1日)` 到次年 1 月 1 日（迄日不含）；不會在原交集的週年切點提前失效。週年制則以來源完整期間使用與結算。

例：2024-07-01 到職，8 小時／日，沒有排除期間，採曆年、曆月比例、保留原值，接管起日及制度生效日皆為 2025-01-01：

| 來源／配置 | 日數與小時 | 期間 |
| --- | --- | --- |
| 2025-01-01 滿半年來源 | 完整 3 日＝24 小時 | 原來源至 2025-07-01（不含） |
| 半年來源配置 2025 | 3 日＝24 小時 | 折算交集為 1/1～7/1；曆年使用到 2026-01-01（不含） |
| 2025-07-01 滿一年來源 | 完整 7 日＝56 小時 | 原來源至 2026-07-01（不含） |
| 滿一年來源配置 2025 | 7×6/12＝3.5 日＝28 小時 | 2025-07-01～2026-01-01（不含） |
| 同一來源配置 2026 | 3.5 日＝28 小時 | 折算交集為 2026 上半年；曆年使用到 2027-01-01（不含） |

2025 年已取得來源完整合計 10 日，但 2025 配置為 6.5 日＝52 小時，另有 28 小時配置至 2026；這 28 小時不能在年終再遞延加一次。2026 若滿兩年仍在職，另一個 10 日來源取得後，該年配置再加 5 日，合計 8.5 日；取得前的 5 日只能是預估。

### 保留原值與無條件進位

| 模式 | 結果 |
| --- | --- |
| 保留精確原值 | 用整數字串分子／分母保存，例如 `1/3` 小時；畫面 `0.333…` 是摘要，不拿摘要回算 |
| 無條件進位至小數第 1 位 | 同員工、同配置年度各段先加總，再算 `ceil(日數×10)/10`；精確 7.1 不會誤變 7.2 |

例：7.01→7.1、7.10→7.1、7→7、0.01→0.1。這不是四捨五入，也不逐來源各進位再加總。分次取得新來源時，依同年度已入帳原值與進位差額重新核對，只記錄必要差額；已休、預占及已結算來源不因進位重算而被收回。

精度策略只用於新給假日數，不把既有請假時數、預占、負調整或工資再套一次進位。例：每日 8 小時、比例型 1/3、2025 原始配置 6.5 日，精確給假為 `52/3` 小時；再調整 `1/3` 小時，結果為 `53/3`，不先改寫成 17.67 小時。正式 SQLite 備份與重啟保留分子分母；CSV／JSON 匯出不是資料庫還原檔。

## 7. 接管、請假扣抵與歷史資料

接管前先確認原人工額度的核給、已休、預占、已結薪及遞延，將核實剩餘帶入「期初未休餘額」。例如原人工全年 80 小時，核實應接管餘額 5 小時，接管後另有本年度新取得配置 52 小時，精確帳可用是 57 小時；不會把原人工 80 再加進來。接管日期前已取得的來源不會整批重發，接管後取得的來源才按有效制度核給。

首次確認入帳後，原人工表單及 Excel 不得覆寫受管理的同員工／特休／接管適用年度；使用「精確調整」。舊人工資料保留作對帳，但查餘額時以精確權利帳呈現，不重複加總。不同假別的人工額度仍按原流程管理。

請假依實際日期扣適用來源，遞延來源優先。待審預占、核准使用、駁回／撤回釋放、紙本修正及作廢都保留原單關係，額度流水在同一交易更新。舊單若跨來源期間、跨年度或接管邊界且缺每日時數，先在人工額度的「舊單／跨年每日扣抵分配」核對；這只補扣抵分配，不改原單日期、時數、狀態或審核人。

刪除員工會停用其精確權利帳及移除待用年資設定，原批次及流水保留供歷史稽核。重新使用同工號不會承接前人的帳，不以工號相同直接重用舊權利。

## 8. 員工與代辦主管怎麼看

員工工作台「請假申請」的本人額度旁有「查看年資特休計算明細」。主管代辦工作區先選已授權員工，再按「查看代辦員工特休明細」。視窗可選年度、展開計算快照、權利來源、已休、預占、可用及結算／異動。

兩個入口只提供授權對象的已入帳快照，不提供全員政策、年資對帳證據、比例依據或協商同意文件。主管授權撤回後，原登入也不能再讀該員工。登出或切換身份會清除明細與暫存，舊請求回應不會回填其他身份的畫面。

## 9. 常見疑問與處理

| 問題 | 說明與處理 |
| --- | --- |
| 為何完整管理者看得到卻不能給假？ | 查看／人工調整和新增三項特休權限分開；請系統管理者明確委派對應權限 |
| 到職週年到了，為何餘額沒增加？ | 沒有背景自動入帳排程；需核對制度與年資，試算並由授權人確認 |
| 修改員工名冊到職日就會重算嗎？ | 不會改寫既有批次。名冊與已核對年資不同會阻擋後續給假，先做年資版本核對 |
| 為何半年 3 日之後又給 7 日？ | 不同資格來源分開取得，並非只補 4 日；年度配置另依制度分段 |
| 本年度日數為何少於完整已取得來源？ | 一部分可能配置後續年度；展開來源與各年度配置核對，不能只看一個年度數字 |
| 明年配置是否就是結轉？ | 不是。已取得來源的後續年度配置已存在，協商遞延另由未休餘額產生 |
| 顯示小數末尾有省略號？ | 為顯示摘要，完整分子／分母及公式在明細與 JSON，不會把截斷值寫回帳本 |
| 為何「待確認」不能按確認？ | 展開列處理缺年資、特殊日期未核對、版本衝突、預占或每日分配等原因；整批有一人阻擋就不能局部完成 |
| 為何顯示新版本已記錄但未套用？ | 修訂影響既往權利，已保留待核對提案及封鎖後續給假；原有效版本仍在，不是套用成功 |
| 同年度改工時或小數規則為何不給？ | 同年度既有及新增配置不能混用。須完成專用政策／歷史對帳，不能直接改舊值繞過 |
| 為何結算還顯示待審？ | 待審只是預占，先處理審核或撤回；不能把它當成已休或自動釋放 |
| 不打算遞延，是否不用處理？ | 應逐來源列待未休工資，由薪資責任人另行核定及付款；不是留白就算結清 |
| 已遞延是否可以再遞延？ | 不可以；到次年度終結或離職仍未休，轉為待未休工資處理 |
| 離職只結今年餘額可以嗎？ | 不可以只以今年配置作上限；契約終止畫面涵蓋此人全部已取得來源，含後續年度配置 |
| 為何 Excel 拒絕匯入已接管特休？ | 人工表單不能覆寫精確來源帳；請在年資特休使用獨立「精確調整」 |
| 全薪／半薪會改給假天數嗎？ | 不會。假別給薪標記不參與本功能額度比例，也不自動計薪 |
| 預覽逾期、切換身份或資料異動？ | 重新整理並重新試算；不手動修改 revision、digest 或改用其他人的預覽 |
| 入帳後取消舊假單，遞延會一起加回？ | 額度回原來源，已結算來源需再次核對其新增剩餘；不自動同時加回下一年度 |
| JSON 或畫面可當作已通知員工證明嗎？ | 是可查閱的計算與帳務資料，不等於已完成公司應辦的通知／書面通知。仍須記錄實際通知方式及證據 |

## 10. 法規與本功能邊界

法規查核日：2026-10-17。法定年資級距及取得權利採 [勞基法第 38 條](https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=N0030001&flno=38)；行使期間及符合資格後 30 日內告知義務參照 [施行細則第 24 條](https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=N0030002&flno=24)。上述來源不表示每一種留停、重聘、部分工時或公司優惠約定都能免核對直接套用。

未休工資的正常工資基準、原年度遞延基準、給付期限及遞延優先扣除規則參照 [施行細則第 24-1 條](https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=N0030002&flno=24-1)。本功能只提供未休來源與數量供薪資作業核對，沒有完整薪資項目、核薪單、付款憑證或工資清冊通知流程；待工資狀態不能當作已履行給付義務。

月底／閏日、曆月與實際日數折算、無條件進位是明確可見且需確認的產品規則；是否適合個別員工仍須核對公司制度與官方解釋。不得因畫面能算出數字就省略年資資料、協商及權利對帳。
